# 마이페이지 · 구독 `/mypage/subscribe`

> 구현이 끝난 화면입니다. 코드에서 읽히지 않는 **계약·결정·함정과 남은 일(이용요약 목, 확인 리스트)** 만 적습니다. 구조·문구 원문은 코드(`pages/mypage-subscribe`, 각 feature, `entities/subscription`)와 각 슬라이스의 `locales/ko.json`을 봅니다.
> 목 데이터 규칙·시안 오류 통일·하위 화면 쿼리·반응형·빈 상태 공통은 [account.md](account.md) §1·§3 공통을 따릅니다.

## 1. 목적과 범위

- 광고주가 구독 상품을 비교·결제하고, 이용량을 보고, 정기결제 카드·구독·결제 내역을 관리합니다. PRD 5.3: 신용카드 정기결제, 월간/연간, 라이브형·어플리에이터형은 "준비중", 구독 전에도 데모 체험 무제한.
- **Master(MASTER·ADMIN)만** 들어옵니다(구독 탭만 비로그인 허용, §3 공통). Sub ID는 권한과 관계없이 못 들어오고 LNB 구독 메뉴가 흐립니다([main.md](../main.md) "LNB 메뉴 구성과 권한"). 모든 구독 API도 Sub는 403입니다.
- **구독 상품은 모집형·PICK형 2개**입니다. 브랜드형·공구형은 구독 단위에서 통합되어 세부 유형 선택이 없습니다. 캠페인 단위로는 구분되므로 캠페인 기준으로 나눠 보이는 곳(상품 카드 배지·상세보기·이용요약 막대와 하단 카드·계정 설정 캠페인 할당의 "세부 상품")은 시안대로 둡니다. 상품은 늘어날 수 있어 목록을 배열 데이터로 다룹니다.
- 가격 정책이 없어 금액은 서버 더미 값이고, 시안의 금액 불일치(199,999 / 199,000)는 신경 쓰지 않습니다.
- API는 모두 연동했고 **이용요약만 API가 없어 목**입니다(B-1, 개발 서버에서만 목, 빌드는 그 탭이 "준비 중").
- **환불 기능은 제공하지 않습니다**(사용자 결정). 시안의 환불 패널·환불 알럿·"환불 요청" 버튼은 만들지 않습니다.

## 2. Figma 기준

- 파일 `a4XCjbdpUcHsm71V1ZucPb`, 페이지 "✔️ 마이페이지"(`6886:40437`)의 `{PC·TAB·MO} / Subscribe` 프레임(결제내역 TAB 일부는 `TAB / My Page / Bizmoney / Payment List`). 구독 탭·결제 화면은 2026-11-02 시안, 그 밖은 구독 Change log 3.0.5 기준입니다.
- 페이지가 다시 만들어질 때마다 node ID가 바뀌어(`10061:*`는 이미 없음) 이 문서에는 ID를 적지 않습니다.
- 프레임 이름이 모두 "Subscribe"지만 이용요약·결제내역 화면이 섞여 있습니다. 주석의 숨은 보조 문구("확인 클릭 시, 결제 / 충전 내역 - Default 화면으로 이동…" 등)는 복붙 잔재라 따르지 않습니다.
- 정기결제 카드 0장("카드 추가" 칸만) 시안은 없습니다.

## 3. 확정 결정

### 공통

| 항목 | 결정 |
|---|---|
| 경로·탭 | `?tab=` `plans`(기본)·`usage`·`payments`(구독·이용요약·결제내역), 잘못된 값은 `plans`. 탭은 모든 기기에서 글자 폭대로 왼쪽 정렬(MO도 균등 폭 아님) |
| 비로그인 | **구독 탭(상품 카드)은 비로그인도 봅니다**(마이페이지 QA 2026-11-16, 상품 API `GET /v3/mypage/subscription/plans`가 비로그인을 허용). 셸은 비로그인 헤더·LNB이고 탭 줄 3개는 그대로 보이며, 이용요약·결제내역 탭과 "구독하기"는 로그인 안내 알럿("로그인하러 가기" → `/login`)을 띄웁니다. 주소로 다른 탭·결제 화면(`?panel=checkout`)을 넣어도 구독 탭을 보이고, 구독 목록·카드 API는 부르지 않습니다. 로그인 후 원래 화면으로 돌아오는 흐름은 두지 않습니다. 로그인한 Sub ID는 계정 설정으로 보냅니다(P-23) |
| 완료 알럿 | 결제 완료·구독 해지 완료·결제카드 변경 완료는 **"확인" 하나만**(시안의 "취소"는 두지 않음) |
| 빈 상태 | 결제 내역은 검색창이 없어 필터 결과 없음은 공통 `list-filter` 문구(빅버드 머니와 같음). **결과가 0건이면 페이지네이션을 숨깁니다**(빈 화면 시안의 페이지네이션은 샘플). **배치(QA 2026-11-10)**: PC는 표 머리글을 두고, TAB·MO는 머리글·테두리 없이 안내만 둡니다(TAB 시안은 테두리 박스지만 MO와 맞추라는 QA 2026-11-13에 따라 테두리를 뺌, 디자인팀 확인 전). MO 내역은 빈 상태일 때 툴바와 안내 사이가 8px(데이터가 있으면 16px) |
| 시안 오류 통일 | "결재액"→"결제액", "결제방법"→"결제 방법", 섹션명 "정기결제 카드", "결제 완료" 배지 회색(PC 기준), 일별 섹션 "이용 현황"·차트 "일별 이용량"(P-4). MO 탭 라벨 오기는 위치대로 "구독"·"이용요약"·"결제내역" |

### 구독 탭

| 항목 | 결정 |
|---|---|
| 월간/연간 | 기본 **월간**(PC 시안 기준, MO 시안은 연간). 연간은 두 줄로 위에 할인 전 "연 ○원"(줄 긋기)·아래 결제 총액 "연 ○원"(`yearlyPrice`). **할인 전 연 금액은 프론트가 `monthlyPrice × 12`로 계산**(서버에 요청하지 않음, 사용자 결정) |
| 상품 카드 | 라이브형·어플리에이터형은 준비중(가격 자리 "준비 중", 배지 "미정", "준비중" 비활성 버튼). MO 시안의 "모집동의서"·"Text"는 오기라 PC 문구 |
| 상세보기 | 카드마다 따로 펼침. **전환 효과 없이 바로 열고 닫음**(높이 전환이 어색해 제거, 사용자 결정) |
| 카드 강조 | **호버는 링이 아니라 카드 배경을 연한 회색(accent/50)으로 바꿉니다.** 시안의 "Focused" 링과 그 전환은 쓰지 않음(디자인팀 QA 2026-11-06). 카드 자체는 클릭 동작 없음 |
| 구독 중 | 구독 목록에 있는 상품은 primary 테두리 + 비활성 "구독 중". 해지 예정이어도 종료일까지 "구독 중", 결제 실패(`paymentFailed`)도 P-17 전까지 "구독 중". **모집형·PICK형은 동시에 구독할 수 있어** 다른 상품의 "구독하기"는 활성. 구독 중인 상품의 결제 화면 주소로 바로 들어오면 결제 화면 대신 구독 탭(카드 0장이어도 카드 등록 알럿 없음). 서버도 이용 중·해지 예정 상품 결제를 `400 ALREADY_SUBSCRIBED`로 거절 |
| 이용 안내·상품 비교 표 | 두지 않음(이용 안내는 2026-11-02 시안에서 삭제, 비교 표는 보류) |

### 결제 흐름

| 항목 | 결정 |
|---|---|
| 결제 화면 | `?panel=checkout&plan=…&period=monthly\|yearly`(탭 없음, 뒤로가기로 구독 탭, `period`가 없거나 잘못되면 월간). 시안의 "세부 유형" 행·제목의 "브랜드형"과 결제 요약의 "결제 카드" 행(결제 수단이 대신함)은 뺌. **PC에서는 결제 요약이 스크롤해도 위쪽에 고정(sticky)**(디자인팀 QA 2026-11-06) |
| 연간 표기 | 결제 화면 시안은 월 구독용 하나라 **월 단위 텍스트만 연 단위로 바꿉니다**(사용자 결정): "연 ○원", "결제 즉시 1년 이용 시작", "1년 단위로 자동 갱신되며, 매년 정기결제가 진행됩니다." 연간은 `yearlyPrice`를 한 번에 결제 |
| 카드 없음 | 등록 카드가 0장이면 "구독하기"(결제 화면 주소 직접 진입 포함)에서 결제 화면 대신 알럿 "결제 카드 등록". "결제 카드 등록하기"는 결제내역 "카드 추가"와 같은 이니시스 카드 등록으로 이동하고, **등록하고 돌아오면 구독하려던 상품·주기의 결제 화면을 다시 열어 이어서 결제**합니다(탭 전체가 떠났다 오므로 떠나기 전에 돌아올 쿼리를 남겨 둠, 사용자 결정). 등록 실패는 구독 탭에서 토스트. 결제창에서 카드 등록과 첫 결제를 함께 하는 `new-card` 흐름은 쓰지 않음(사용자 결정) |
| 결제 수단 | 등록 카드 타일 + 할부 Select. 기본 카드가 맨 앞이고 처음부터 선택됨. 선택하지 않은 타일의 호버 링은 시안에 없고 사용자 결정. 카드 1장 배치는 P-10 |
| 기본 카드 변경 | **기본 카드로만 결제합니다.** 다른 타일을 누르면 알럿 "기본 카드 변경" → 확인하면 `PUT …/billing-cards/{id}/default`(결제내역 "결제 카드로 등록"과 같음)로 바꾸고 그 카드가 선택됨. 변경은 이미 구독 중인 상품의 다음 정기결제에도 적용됨 |
| 할부 | **월간은 "일시불" 고정·비활성, 연간만 선택.** 고를 수 있는 것은 기본 카드의 Select뿐(P-15). 옵션 "일시불"·"2개월"~"12개월"(시안의 "1개월"은 서버가 일시불로 처리해 뺌). 체크카드(`cardKind: debit`)는 일시불 고정(P-13). 일시불이면 `installmentMonths`를 보내지 않음 |
| 결제 | **기본 카드로 바로 결제**(결제창 없음): 결제 서버 `POST /v3/subscription/billing/subscribe/saved-card`(`{token, productType, billingPeriod, installmentMonths?}`, 토큰은 `GET …/init`). 성공하면 `?result=success`로 구독 탭. 실패는 코드별 토스트(보조 카드로 재시도하지 않음) |
| 결제사 거절 사유(i18n 예외) | 실패 응답의 `pgMessage`(예: "잔액부족")를 토스트 설명으로 **한국어 원문 그대로** 덧붙입니다(번역하지 않음). 서버 메시지를 노출하지 않는 i18n 규칙의 예외로 사용자 요청. 복귀 주소의 `?pgMessage=`는 누구나 만들 수 있어 100자까지만(B-5) |
| 결제 완료 | `?result=success`로 돌아오면 구독 데이터를 다시 읽고 "결제 완료" 알럿 → 확인하면 쿼리를 지우고 구독 탭. 카드 등록에서 `?result=fail&reason=코드`로 돌아오면 코드별 토스트 |

### 이용요약 탭

목 단계(B-1·B-3)라 API가 나오면 결정이 바뀔 수 있습니다.

| 항목 | 결정 |
|---|---|
| 상품 전환 | 세그먼트 `?type=recruit\|pick`, 기본은 구독 중인 첫 상품 |
| 미구독 | 전체 미구독·고른 상품만 미구독 모두: 세그먼트·카운트 카드·필터는 두고 카운트 값 "-"·진행 바 0, 차트 자리에 빈 상태, 하단 카드 없음 |
| 카운트 카드 | 큰 숫자 = 사용, 진행 바 = 사용 ÷ (사용 + 잔여). 한도는 **상품별** |
| 필터 | 지표는 **하단 카드 지표 전부**(시안은 2개, 사용자 결정). 연도는 데이터가 있는 연도, 월은 1~12월(올해는 이번 달까지). 시안 옵션 누락은 시안 오류 |
| 차트 | 범례는 하단 카드 제목의 색 점이 대신함(시안). PC 월별만 12개월 전체, **나머지는 캐러셀**(PC 일별 11·TAB 7·MO 3개씩, 보이는 개수만큼 넘김, 처음에는 이번 달·오늘이 보이게, 사용자 결정) |

### 결제내역 탭

| 항목 | 결정 |
|---|---|
| 정기결제 카드 | 최대 2장(주석). **2장이면 기본 카드에 ⋮ 없음**(시안), 여분 카드 ⋮ → "카드 삭제"·"결제 카드로 등록". **카드가 한 장뿐일 때만** 기본 카드 ⋮에 "카드 삭제"(구독이 없을 때 마지막 카드를 지울 수 있게 시안에 없는 메뉴 추가, 사용자 결정). 기본 카드를 지우려면 먼저 여분 카드를 기본으로 바꿈(여분이 있는데 기본을 지우면 남은 카드가 자동으로 기본이 되어 의도치 않은 카드로 결제될 수 있어서, 사용자 결정) |
| 카드 추가 | 별도 카드 등록 화면 없이 **KG이니시스 빌링키 발급 결제창**(이니시스가 등록 UI 제공, 사용자 결정). 성공해 돌아오면 카드 목록을 다시 읽고 토스트 후 결제내역 탭 |
| 카드 삭제(함정) | 낙관적 갱신, 실패하면 되돌림. 결제가 이어지는 구독(`active`·`paymentFailed`)이 있으면 서버가 반드시 거절(409 `DEFAULT_CARD_IN_USE`)하므로 **한 장뿐인 기본 카드에도 삭제 메뉴를 보이지 않음**(보였다 거절되면 카드가 사라졌다 되돌아오는 깜빡임). 해지 예정(`cancelScheduled`)·구독 목록을 못 읽은 경우는 백엔드 문서가 갈려 서버 판단에 맡김 |
| 구독 해지 | 해지 후 종료일까지 행 버튼은 비활성 "해지 예정", 구독 탭은 "구독 중" 유지 |
| 결제 내역 범위 | **구독 결제만**(사용자 결정). 빅버드 머니 충전은 [money.md](money.md)에서만 봄. MO 샘플의 "비즈머니 50,000원" 행은 복붙 잔재 |
| 결제 내역 툴바 | **검색창 없음**(사용자 결정, 시안의 검색창은 그리지 않음). MO "필터" → 모달(`?panel=filter`, 탭이 숨는 것은 의도). 새로고침은 필터를 초기화하고 다시 읽음 |

### 백엔드

구독 API는 v2에 없어 새로 만들어졌습니다. 확정된 계약(Swagger만 봐서는 놓치기 쉬운 것):

- **서버 구분:** 조회·카드 관리·해지·결제 내역은 V3(`/v3/mypage/subscription/…`), 기본 카드 결제(`saved-card`)·카드 등록(`cards/register`)은 결제 서버. 에러는 `{ result: false, reason: 코드 }`.
- **카드 등록:** `GET …/init` 토큰(10분 유효) → 결제 서버 `cards/register` → 응답 값을 숨은 form으로 `issuanceUrl`에 POST(전체 이동) → `{origin}{redirectUri}?result=success&cardId=…` 또는 `?result=fail&reason=코드[&pgCode&pgMessage]`. 복귀 도메인은 프론트가 정하고 서버는 검증하지 않음. 금액·주문번호·서명은 서버가 만들고 머니 충전의 `encryptUserIdx`는 쓸 수 없음. 첫 카드는 기본 카드가 됨.
- **카드:** 결제 중인 구독이 있으면 기본 카드 삭제는 409 `DEFAULT_CARD_IN_USE`, 보조 카드는 언제든, 구독이 없거나 모두 해지했으면 기본 카드도 삭제되고 남은 카드가 기본이 됨. 없는·남의 카드는 404 `BILLING_CARD_NOT_FOUND`.
- **해지:** 응답 `{ subscriptionId, productType, canceledAt, serviceEndAt }`, 종료일까지 이용 후 끝남. 이미 해지 409 `ALREADY_CANCELED`, 없는·남의 구독 404 `SUBSCRIPTION_NOT_FOUND`.
- **결제 내역:** 성공한 구독 결제만 최신순, `from`·`to` 양 끝 포함(KST, `YYYY-MM-DD`). 일시불 `card`, 할부 `cardInstallment`(+ `installmentMonths`).
- **정기결제 실패:** 구독 목록 항목의 `status`(`active`·`cancelScheduled`·`paymentFailed`)와 `nextRetryAt`(`paymentFailed`일 때만). 실패하면 즉시 이용이 멈추고 하루 간격 최대 3회 기본 카드로 재결제, 모두 실패하면 목록에서 빠짐. 해지하면 재결제가 멈추고 바로 빠짐. 실패 사유 필드와 실패 알림은 없음. 프론트는 필드를 받아 두었고(모르는 상태는 `isCancelScheduled`로 가림) 화면은 P-17~P-22 답 후.
