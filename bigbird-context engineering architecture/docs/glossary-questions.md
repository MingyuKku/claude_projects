# 용어집 질의 목록 (glossary-questions)

> 화면별 다국어 이관 중 만난 **서비스 고유 용어**를 모아 두고, 사용자가 나중에 한 번에 답하기 위한 문서입니다.
> 답을 받으면 `docs/prd.md` 7장 용어집에 en/ja/zh-CN 표기를 기록하고, 이 문서의 해당 행을 "확정"으로 옮깁니다.
> 규칙의 원본은 `.claude/rules/i18n.md`이며, 이 문서는 그 운영 방식입니다.

## 운영 방식

- 에이전트는 화면을 이관하다 고유 용어를 만나면 **질문으로 멈추지 않고** 이 문서에 추가합니다.
- 답을 받기 전까지 해당 용어는 **한국어 원문 그대로** 모든 언어 파일(`en`·`ja`·`zh-CN`)에 둡니다. 문장 안에 있으면 그 부분만 한국어로 남깁니다.
- 번역 키는 정상적으로 만들고(문구를 하드코딩으로 되돌리지 않음), 값만 한국어입니다. 답을 받으면 값만 바꿉니다.
- 같은 용어는 한 번만 적고 "사용 화면"에 계속 추가합니다.

## 용어 판단 기준 (느슨하게)

**고유 용어로 보는 것**: 이 서비스가 자기만의 뜻으로 정의해 쓰는 말.

- 서비스·기능·지표 이름 (예: 빅버드 머니, 브랜드 지수, 공구 지수)
- 서비스 안에서 고유명사처럼 쓰는 분류 (예: 모집형 / pick형 캠페인)

**질문하지 않고 에이전트가 번역하는 것**: 업계나 일상에서 널리 통용되는 말.

- 빅버드(서비스명), 인플루언서, 크리에이터, 광고주, 캠페인, 로그인, 회원가입, 비밀번호, 약관, 구독 등
- 버튼·안내·에러·날짜·수량 표현

애매하면 질문하지 않고 번역한 뒤 PR 설명에 "번역 판단" 항목으로 남깁니다.

### 번역 제안 (2026-10-20 제안, 2026-10-21 승인 — PRD 7장에 반영, "어플리에이터형"만 보류)

사용자 의견: 비슷한 인플루언서 마케팅 플랫폼(Modash, Aspire, 크리플래닛, 태그바이, 피처링 등)의 용어를 참고하면 번역에 문제가 없다. 아래는 업계에서 흔히 쓰는 표현을 기준으로 한 **제안**이며, 각 사이트의 실제 표기와 대조한 것은 아닙니다. 승인되면 PRD 7장 용어집으로 옮기고 번역 리소스에 반영합니다.

| 용어 | en | ja | zh-CN |
|---|---|---|---|
| 빅버드 머니 | Bigbird Money | ビッグバードマネー | Bigbird 余额 |
| 모집형 / PICK형 | Recruitment / PICK | 募集型 / PICK型 | 招募型 / PICK型 |
| 브랜드형 / 공구형 | Brand / Group Buy | ブランド型 / 共同購入型 | 品牌型 / 团购型 |
| 라이브형 / 어플리에이터형 | Live / Affiliate | ライブ型 / アフィリエイト型 | 直播型 / 联盟型 |
| 라이브커머스형 / 라이브클래스형 | Live Commerce / Live Class | ライブコマース型 / ライブクラス型 | 直播带货型 / 直播课程型 |
| OTA형 / 소상공인형 | OTA / Small Business | OTA型 / 小規模事業者型 | OTA型 / 小微商家型 |
| Master ID / Sub ID | Master ID / Sub ID | マスターID / サブID | 主账号 / 子账号 |
| AI 포스팅 가이드 / AI 원고 컨펌 | AI Posting Guide / AI Draft Review | AI投稿ガイド / AI原稿チェック | AI发帖指南 / AI稿件审核 |
| 인플루언서 매칭 / 인플루언서 마켓 | Influencer Matching / Influencer Market | **マッチング / マーケット**(사용자 결정 2026-10-20) | 网红匹配 / 网红市场 |

- "어플리에이터형"은 Affiliate로 보고 제안했습니다. 철자·뜻 확인이 필요합니다.
- 인플루언서 매칭·마켓의 ja 표기는 "インフルエンサーマッチング"(12자)·"インフルエンサーマーケット"(13자)가 업계 표준이지만 LNB(230px)에 넘쳐 **"マッチング"·"マーケット"로 줄이기로 결정**했습니다(사용자 결정 2026-10-20).
- 라이브커머스형은 앞으로 생길 구독 모델(라이브형)의 세부 유형입니다(사용자 답변). 랜딩의 "공구형 하위" 표기는 랜딩 시안 기준으로 그대로 둡니다.

## 서버 번역 요청 (참고)

서버가 주는 데이터는 용어집이 아니라 스펙 "다국어" 절의 **서버 코드·값** 표에서 관리합니다. 상태·유형처럼 종류가 정해진 값은 코드(enum)로 받아 프론트 번역 키로 보여 주고, 카테고리·은행명 같은 DB 목록 값은 서버 값을 그대로 표시합니다(`.claude/rules/i18n.md` "서버 데이터").
