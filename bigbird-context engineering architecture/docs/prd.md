# bigbird PRD

> 프로젝트 전체의 목적·범위·용어를 정의합니다. 기능 단위 상세는 `specs/[<그룹>/]<feature>.md`에 둡니다.
> "미정"은 확정되지 않은 항목입니다. 에이전트는 미정 항목을 추측으로 채우지 말고 질문합니다.

## 1. 서비스 개요

bigbird는 **광고주가 자사 상품(서비스)에 적합한 크리에이터(인플루언서)를 빅데이터 분석으로 찾아 매칭해 주는 B2B 서비스**입니다.
이 저장소는 그 서비스의 **광고주용 웹 클라이언트**입니다.

기존 광고주 웹(`bigbird-client-fe`, Vue 2, PC 전용)을 React로 다시 만드는 마이그레이션입니다. 디자인은 전면 개편되고 반응형이 추가됩니다. 화면 구성은 새 Figma 시안을 따르며, 구버전 페이지와 1:1로 대응하지 않습니다. 구버전은 기능과 API를 확인하는 참고용으로만 씁니다. 구버전의 Biglink AI 영역(`/ai/*`, `/contents`)은 마이그레이션하지 않습니다.

## 2. 사용자

| 구분               | 설명                                                             | 이 프로젝트 포함 여부                |
| ------------------ | ---------------------------------------------------------------- | ------------------------------------ |
| 광고주 (기업 고객) | 인플루언서를 검색·추천받고 캠페인을 등록하는 주 사용자           | 포함                                 |
| 비로그인 방문자    | 홈에서 서비스 소개를 보고 문의하거나 검색을 미리 체험하는 사용자 | 포함                                 |
| 인플루언서         | 캠페인 제안을 받는 크리에이터                                    | **제외** (이 프로젝트는 광고주 전용) |
| 내부 운영자        | 서비스 관리                                                      | 기존 ADMIN 계정 전환(`/a/change`) 포함. 그 외 범위는 미정 |

## 3. 환경·공통 요구

- **디바이스:** 반응형 (모바일 · 태블릿 · 데스크톱)

  | 레이아웃 | 화면 폭                | 시안 기준 크기 |
  | -------- | ---------------------- | -------------- |
  | 모바일   | 768px 미만             | 360 × 600      |
  | 태블릿   | 768px 이상 1440px 미만 | 768 × 700      |
  | 데스크톱 | 1440px 이상            | 1440 × 800     |

- **언어:** 한국어(기본·fallback), 영어, 일본어, 중국어(간체, `zh-CN`). 모든 사용자 노출 문구는 다국어 대상입니다. 라이브러리는 `i18next` + `react-i18next`이며 런타임은 `src/shared/i18n`(초기화·포맷터)과 `src/app/i18n`(리소스 수집·언어 결정·폰트)에 있습니다. 일본어·중국어 폰트(Pretendard JP, Noto Sans SC)는 해당 언어일 때만 내려받습니다.
  - 번역 파일은 슬라이스별로 둡니다. 한국어가 원본입니다. 일반 문구는 에이전트가 번역하고, 미확정 서비스 고유 용어는 `docs/glossary-questions.md`에 모아 일괄 확인한 뒤 7장 용어집에 기록합니다. 답변 전에는 모든 언어에서 해당 용어의 한국어 원문을 유지합니다.
  - 서버가 주는 코드성 데이터(카테고리 등)는 백엔드가 번역합니다. 에이전트가 화면 작업 중 대상을 정리해 질문하고, 백엔드 개발자에게 번역을 요청합니다.
  - URL에 언어 접두어를 두지 않습니다. Figma에 언어 전환 UI가 없어 브라우저 언어로 정하고(번체 중국어 포함 중국어는 간체), 지원하지 않는 언어는 한국어로 표시합니다. QA는 `?lng=en` 같은 쿼리로 언어를 바꾸며, 선택은 브라우저에 저장됩니다.
  - 상세 규칙: `.claude/rules/i18n.md`
- **지원 브라우저·접근성 기준:** 미정
- **디자인 원본:** Figma [(개발용) 빅버드_마이그레이션 V.3.0.0](https://www.figma.com/design/k5VBKeB2apb3wb4l4Af3sZ). 페이지별 node-id는 6장 표에 있습니다. 기획 와이어프레임(PC 전용, 참고용)은 [(기획운영팀) 서비스별 와이어프레임](https://www.figma.com/design/n8kmvAFsnsWmDZD17tNJ4e?node-id=59-1026)입니다.
- **API 원본:** OpenAPI 명세 (`https://api.stage.client.bigbird.co.kr:38443/v3/api-docs`). 요청·응답 스키마와 오류·인증 정의가 대부분 비어 있어 백엔드에 보완을 요청했습니다. 고객센터는 `docs/customer-center-api.md`에 정리했습니다. 보완 전에는 목 데이터를 사용합니다.
- **실시간 채팅:** Firestore를 사용합니다(고객센터, 인플루언서 채팅). 운영·인플루언서·마켓 앱과 같은 Firebase 프로젝트를 공유하므로, **SDK만 최신 버전으로 쓰고 기존 데이터 구조(컬렉션·필드)와 보안 규칙은 바꾸지 않습니다.** 필드를 추가해야 하면 같은 프로젝트를 쓰는 앱들과 먼저 합의합니다. Firebase SDK 도입은 `dependencies` 규칙에 따라 승인을 받습니다.

## 4. 사용 시나리오 (예)

스킨케어 신제품을 홍보하려는 광고주가 20대 여성 타깃, 인스타그램 중심으로 인플루언서를 검색하고, 필터로 좁히거나 AI 추천 도우미에게 조건을 말해 추천받은 뒤, 마음에 드는 인플루언서를 즐겨찾기에 담고 캠페인을 제안합니다.

## 5. 기능 목록

### 5.0 메뉴 구조 (사이드바)

시안의 사이드바 메뉴가 서비스의 정보 구조입니다.

- 캠페인 등록하기 (버튼)
- 홈
- 캠페인
- 인플루언서: 인플루언서 검색 / 인플루언서 관리 / 채팅
- 커머스 판매현황 (시안 없음)
- 마이페이지: 구독 / 빅버드 머니 / 계정 설정
- 고객센터: 빅버드 문의 / 구매자 문의
- 이용 가이드 (하단)

데스크톱은 사이드바를 펼치거나(230px) 아이콘 레일(56px)로 접을 수 있습니다. 태블릿은 레일이 기본이고 열면 오버레이로 뜹니다. 모바일은 햄버거 메뉴로 엽니다.

### 5.1 홈 · 탐색

- 홈(`/`)은 로그인·비로그인 모두 접근 가능하며 **헤더 형태만 로그인 상태에 따라 달라집니다.** 서비스 소개는 `/introduction`에서도 제공합니다.
- 홈의 목적: 서비스 소개, 문의 유입.
- 홈은 **검색 입력**(제품 정보 문장 + 플랫폼)과 주요 화면 카드를 둡니다. 결과는 별도 화면(`/influencers/search`)에서 보여 주며, 비로그인 방문자에게는 **검색과 결과 목록 일부 미리보기**만 보여 줍니다 (일부의 기준, 상세·전체 열람 시 로그인 유도 방식은 미정).
- 디자인 시안의 홈에는 검색 입력(플랫폼 선택 + 자유 입력)과 기능 카드 3개(인플루언서 추천, 캠페인 등록/운영, 요금 안내)만 있습니다. 비회원 검색 결과 화면은 와이어프레임에만 있고 디자인 시안이 없습니다.
- 헤더의 알림 목록이 API 응답 기반인지 실시간(Firestore 구독 또는 브라우저 푸시)인지는 미정입니다.
- 로그인 후 메인 경로는 `/`입니다. 공통 헤더·좌측 LNB를 먼저 연결하며 대시보드 본문 구성은 미정입니다.

### 5.2 인증

- 소셜 로그인: 카카오, 네이버, 페이스북, 애플, 구글 (목록은 "등"이 붙어 있어 추가 가능성 있음).

### 5.3 구독 · 결제

- 광고주는 플랫폼을 **구독**하여 사용합니다. 구독 결제는 **신용카드** 정기결제이며 월간/연간을 고릅니다.
- 구독 상품은 모집형과 PICK형입니다. 라이브형과 어플리에이터형은 "준비중"으로만 노출합니다. 구독 전에도 데모 체험은 무제한입니다.
- **빅버드 머니:** 플랫폼 내에서 쓰는 머니. 충전은 **무통장 입금**(가상계좌)입니다. 시안에 보이는 사용처는 인플루언서 계약 비용과 부가서비스(AI 포스팅 가이드, AI 원고 컨펌)입니다. (환불 정책은 미정)
- 마이페이지의 계정 설정은 Master ID 관리, 회사정보, 계좌정보, Sub ID 관리(캠페인 할당·권한 부여), 알림 설정으로 구성됩니다.

### 5.4 인플루언서 검색 · 추천

- 광고주가 검색할 **인플루언서 플랫폼(예: 인스타그램)을 선택**해 추천받습니다.
- 검색 필터: 팔로워 수, 평균 댓글 작성자 수, 브랜드 지수, 공구 지수, 예상 비용, 평균 조회수 등.
- **AI 추천 도우미 챗봇:** 검색 조건에 맞는 인플루언서를 추천합니다.
- 인플루언서 **상세 페이지:** 스펙을 다양한 차트로 표현하고, 인플루언서가 활동 중인 각 플랫폼의 최근 피드를 받아 보여 줍니다.

### 5.5 즐겨찾기 · 관리

- 인플루언서 즐겨찾기 저장, **즐겨찾기 폴더** 생성.
- 인플루언서 관리 대시보드.

### 5.6 캠페인

- 캠페인 등록: **모집형 / pick형** 중 선택 후 등록.
- 특정 인플루언서에게 캠페인 제안.
- 캠페인 등록·승인·거절에 대한 **알림**. 알림 수신은 **FCM 웹푸시**를 씁니다(권한 요청 방식과 `firebase` SDK·Service Worker 추가는 팀 승인 필요, 세부는 [specs/home.md](../specs/home.md) §5).
- 특정 인플루언서와 **채팅**.
- 캠페인 현황은 단계별 탭(전체, 등록 중, 승인 대기/반려, 진행 중, 종료)으로 봅니다.
- 캠페인 등록은 단계별 입력 마법사이며, 임시저장과 승인 요청 후 상태(승인 검토중, 반려, 재승인 검토중, 승인 완료)를 가집니다. 재승인은 최대 2회입니다.

### 5.7 고객센터

- **빅버드 문의:** 광고주가 운영자에게 문의 남기기 또는 실시간 상담으로 문의합니다. 문의 남기기는 첫 메시지 저장 후 입력창·종료 버튼 없는 읽기 전용 대화로 이동합니다. 열린 문의의 답변 여부와 무관하게 새 문의를 등록하며 기존 문의를 자동 종료하지 않습니다(2026-10-19 확정). 복수 일반 문의 등록은 호환 검증 전까지 연동·공개를 보류합니다. 실시간 상담은 v2 기능 유지와 v3 Figma 구현을 목표로 하며, 필요한 v2·운영 앱 호환 수정은 작업 범위에 포함합니다. 연결 대기는 두 앱 모두 5분으로 맞춥니다. 상담 요청 중에도 메시지를 미리 보낼 수 있고(연결 대기 마감 전까지), 요청 실패·종료 후에는 입력할 수 없습니다. v3 실시간 대화에는 캠페인 카드를 표시하지 않습니다. 운영 앱·v2 대화에 카드가 보이도록 캠페인 문의의 카드 메시지는 계속 보냅니다(2026-10-19 확정). 과거 상담의 v3 이관은 제외하며 v2·운영의 기존 기록은 유지해도 됩니다.
- **구매자 문의:** 광고주가 공구 구매자의 문의(구매자 문의, 상품 Q&A)에 답하고, 주문·캠페인 정보를 함께 봅니다. 상태는 답변 대기 / 답변 완료입니다(재문의는 2026-10-19 디자인 변경으로 없앰).
- 입력은 최대 3,000자이며 파일을 첨부할 수 있습니다.
- **메시지 수정·삭제 (컨펌 대기):** 상대가 읽기 전까지 본인 메시지를 수정·삭제하는 기능을 제안했습니다. 운영 앱 기획·디자인과 백엔드 API가 필요해 범위를 확인 중입니다.
- 상세 동작과 미해결 항목: `specs/customer-center/customer-center.md`

## 6. 릴리스 범위

> **고객센터 최신 범위(2026-10-19):** 기타·캠페인 일반 문의의 첫 텍스트 등록과 읽기 전용 조회가 목표입니다. 기존 1개 제한·추가 메시지·광고주 종료 계획을 대체합니다. 목록·대화 조회는 연결되어 있으나, 복수 문의 등록은 v2·운영 앱 호환 방안 확정 및 앱 간 검증까지 연동·공개를 보류합니다. 현재 작업은 v2 기능을 유지하는 v3 실시간 상담 구현과 v2·운영 앱 호환 수정입니다. 과거 상담 이관은 제외합니다. 구매자 문의·메시지 편집은 후속이며 첨부는 서버 지원 확인이 필요합니다. 상세는 `specs/customer-center/customer-center.md`를 따릅니다.

**시안이 없어 MVP에서 제외** (와이어프레임에만 있음): 로그인·회원가입, 비회원 검색 결과, 캠페인 진행(PICK형·모집형), 모집형 캠페인 등록, 커머스 관리(판매현황·반품·교환·정산·세금계산서). 공구형 캠페인 화면은 와이어프레임에도 없습니다.

- 로그인 화면이 없으므로 MVP 개발 중에는 목 로그인 상태로 인증이 필요한 화면을 확인합니다.
- 캠페인 등록 마법사는 이후 모집형이 같은 단계 구조로 추가될 예정이므로, 단계 구성을 바꿔 끼울 수 있게 만듭니다.
- 5장의 기능 목록은 현재 알려진 범위이며 **앞으로 기능이 더 추가될 예정**입니다. 새 기능은 이 문서에 추가한 뒤 `/spec`으로 상세화합니다.
