## 1. 목적과 범위

- 광고주가 구독 상품(모집형·PICK형)을 비교하고, 구독 중인 상품의 이용량을 보고, 정기결제 카드·구독 결제 상품·결제 내역을 관리합니다. PRD 5.3: 신용카드 정기결제, 월간/연간, 라이브형·어플리에이터형은 "준비중" 노출, 구독 전에도 데모 체험 무제한.
- API와 목 데이터는 [account.md](account.md) §1 규칙을 따릅니다(공개 API가 충분하면 연결, 아니면 목. 목은 화면 구현 확인용이고 구현이 끝나면 흔적 없이 지움). 구독 API는 아직 없어(§7 B-1) 지금은 전부 목입니다. 목 단계의 서버 동작(구독 결제·해지·카드 등록·삭제·변경)은 확인 알럿까지 시안대로 진행하고 마지막에 "준비 중인 기능입니다." 토스트, 값은 바꾸지 않습니다.
- **구독 결제 흐름도 만듭니다**(2026-10-20 사용자 답변). **브랜드형·공구형은 구독 단위에서 통합**되어 구독 상품은 **모집형·PICK형 2개**이고 세부 유형을 고르는 단계는 없습니다. 캠페인을 만들 때는 브랜드형·공구형이 구분되므로, 캠페인 기준으로 나눠 보여 주는 화면(상품 카드 배지·상세보기 설명·이용요약 막대와 하단 카드·계정 설정 캠페인 할당의 "세부 상품")은 시안대로 둡니다(사용자 답변 2026-10-20). 상품은 나중에 늘어날 수 있으므로 상품 목록을 데이터(배열)로 다루고 2개로 고정하지 않습니다. 가격은 정책이 없어 **더미 데이터**이고, 결제 화면 금액 불일치(199,999 / 199,000)는 신경 쓰지 않습니다.
- Master(MASTER·ADMIN)만 들어올 수 있습니다. **Sub ID는 권한과 관계없이 구독에 들어갈 수 없고** LNB 마이페이지 > 구독은 흐리게 비활성입니다(사용자 답변, [main.md](../main.md) "LNB 메뉴 구성과 권한").

### 시나리오

1. LNB 마이페이지 > 구독으로 들어오면 구독 탭(상품 선택)이 열립니다. 월간/연간을 바꿔 보고 상세보기로 상품 설명을 펼칩니다. 구독 중인 상품에는 "구독 중"이 보입니다.
2. "구독하기" → 결제 화면(안내사항 동의) → "결제" → PG 결제창 → 결제 완료 알럿 → 구독 탭.
3. 이용요약 탭에서 모집형/PICK형을 골라 검색·제안 사용량과 월별·일별 이용 차트를 봅니다.
4. 결제내역 탭에서 정기결제 카드를 추가·삭제·기본 카드로 바꾸고, 구독을 해지하고, 결제 내역을 검색·필터하고, 결제 건의 환불을 신청합니다.

## 4. 배치와 Public API

- `pages/mypage-subscribe`: `MyPageSubscribePage`(탭·쿼리 소유, 셸).
- `entities/subscription`: 상품·구독 상태 뷰모델과 목 데이터, 상품 카드(`SubscriptionPlanCard`)처럼 여러 feature가 쓰는 표시 컴포넌트.
- `features/browse-subscription-plans`: 월간/연간 토글 + 상품 카드 목록 + 상세보기(`SubscriptionPlanList`).
- `features/view-subscription-usage`: 이용요약(`SubscriptionUsageDashboard`). 차트는 `shared/ui/chart`(Recharts) 기반, 캐러셀 페이지 계산은 `lib`.
- `features/manage-billing-cards`: 정기결제 카드(`BillingCardList`).
- `features/manage-subscription`: 구독 결제 상품·해지(`SubscribedProductTable`).
- `features/payment-history`: 결제 내역 목록·필터·환불(`PaymentHistory`, `RefundPanel`). 빅버드 머니 스펙의 충전·사용 내역과 툴바·필터 화면 구조가 같으므로, 공통 부분(검색+기간+Select 툴바, TAB·MO 필터 화면, MO 카드 리스트)은 `shared/components`로 올리는 것을 구현 계획에서 검토합니다.
- `shared/config/routes.ts`에 `mypageSubscribe: "/mypage/subscribe"`.
- 세부 분할·props는 `/plan`에서 정합니다.

## 5. 데이터 흐름의 예외

- 구독 API가 없어 목 단계입니다(SWR·Zod 없음). API가 나오면 표준 흐름으로 바꾸고 목은 지웁니다. 뷰모델(`SubscriptionPlan`, `Subscription`, `UsageSummary`, `UsageSeries`, `BillingCard`, `SubscribedProduct`, `PaymentRecord`)만 둡니다.
- 결제 상태·결제 수단은 서버 코드값으로 받아 배지 색·번역 키에 매핑해야 합니다. 코드 체계는 백엔드 확인(§7 B-2) 전까지 목 데이터의 임시 코드(`paid`·`refunding`·`refunded`)로 둡니다.

참고: 정기결제는 보통 **첫 결제 때 카드를 등록(빌링키 발급)하면서 결제**하고, 이후 매달 결제는 서버가 그 카드로 자동 처리합니다. 화면이 필요한 것은 첫 결제와 카드 관리뿐이고, 정확한 방식은 구독 API가 나오면 확인합니다.

## 9. 검증

- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm i18n:check`
- 화면 확인(PC 1440·TAB 768·MO 360, 시안 대조)
  1. 탭 전환·잘못된 `?tab=` 대체, 헤더·LNB 활성
  2. 구독 탭: 월간/연간 전환 시 가격·할인율 색, 상세보기 카드별 펼침, 카드 강조(포커스·호버·펼침), 준비중 카드, 구독 중 표시
  3. 결제 흐름: 구독하기 → 결제 화면(체크 전 결제 비활성, 취소·뒤로가기) → "결제"(목 단계 "준비 중")
  4. 이용요약: 모집형/PICK형 전환(PICK형 매칭 성사 수), 지표·연도·월 Select, 월별/일별, 캐러셀 처음 위치·넘김 단위·끝 비활성(PC 월별은 캐러셀 없음)
  5. 결제내역: 카드 0·1·2장, ⋮ 메뉴 → 결제카드 변경 알럿 → 완료(확인만), 카드 삭제 알럿, 구독해지 알럿(종료일 표시) → 완료 → "해지 예정"(목 단계는 "준비 중" 토스트 후 값 유지)
  6. 결제 내역: PC 표·TAB 2열 카드·MO 카드, PC 인라인 필터·새로고침 초기화, TAB·MO 필터 화면(적용하기 활성 조건, 뒤로가기로 닫힘), 상태별 "환불 요청" 활성(결제 완료만) → 환불 문의 알럿 → "문의하기"로 고객센터 새 문의, MO 페이지네이션(10건)
  7. 화면 구현을 마칠 때 목 데이터·목 분기가 남지 않았는지 확인
- `?lng=en`으로 긴 문구 레이아웃 확인
