# 약관 (이용약관 · 개인정보처리방침)

## 목적

법적 전문(이용약관, 개인정보처리방침)을 `entities/terms`에 정적 데이터로 두고 두 곳이 재사용한다.

- `/terms`: 로그인·소개 푸터 링크에서 열람. 인증 불필요.
- 회원가입 3단계: 항목별 "보기" → 전문 → "동의하기"로 체크. 별도 URL 없이 `/join` 안에서 화면만 전환.

## URL 계약

- `/terms?type=privacy`(정확히 `privacy`)만 개인정보처리방침, 그 외 모든 값(없음·`Privacy`·빈 값 포함)은 이용약관.
- 문서 title은 `약관 `(끝 공백 포함, v2와 동일).

## 제약 (코드에서 읽히지 않는 것)

- 법적 문구는 v2와 **바이트 동일**하다. 포맷터·에디터가 문구·공백·특수문자(‘ ’ “ ” • –)를 바꾸지 않게 주의한다. 문구를 고치면 이 계약이 깨지므로 PR에 의도한 변경임을 명시한다.
- 문구를 고쳤다면 v2 `entities/auth/terms-content.ts`의 `export const PRIVACY_POLICY_CONTENT`부터 끝까지와 이 저장소 `terms-content.ts`의 같은 구간을 `diff`해 변경 범위가 의도와 일치하는지 확인한다.
- 법무 승인된 원문만 반영한다. 시행일·버전 문구도 본문 텍스트 안에 있다.
- 두 화면이 같은 상수를 쓰므로 한 번 수정으로 `/terms`와 회원가입에 동시 반영된다.
- `TermsBlock`에 새 블록 타입을 추가하면 `TermsContent`에도 분기를 추가해야 한다. 분기가 없으면 전부 paragraph로 잘못 렌더된다.

## 동작 결정

- "동의하기"는 토글이 아니다. 이미 체크된 항목도 true로 유지하고, 해제는 목록 체크박스에서만 한다.
- 전문 보기에서 "뒤로"는 동의 변경 없이 목록으로 복귀한다.
- `/terms` 직접 진입 시 `navigate(-1)`의 폴백은 없다(v2와 동일, 미정).

## v2 대비

- `entities/auth` 안의 파일을 `entities/terms` 독립 슬라이스로 분리했다(login·join 공유, auth 로직과 분리).
- 소개 푸터 링크는 v2 `/service`·`/term`에서 `/terms`, `/terms?type=privacy`로 재매핑했다.
- 그 외 본문·블록 구조·`?type` 판정은 동일하다.

## 범위 밖 · 미해결

- 약관 버전·개정 이력, 동의 시점·버전의 서버 기록: PRD 미정, 추측하지 않는다.
- 다국어, 약관 CMS/API 연동, 선택 동의 항목: 범위 밖.
- 법적 문구의 최신성은 법무 확인 사항이다.
