# 비밀번호 변경 (`/changePw`, `/expired`) + 임시 메인 (`/main`)

## 목적

- A. 찾기 후 변경 `/changePw`: 비밀번호 찾기(카카오톡 인증) 성공 후 "비밀번호 변경"으로 진입. 서버가 발급한 **일회용 쿠키 세션**으로 새 비밀번호를 저장한다. 현재 비밀번호·아이디를 모른다. 완료 모달 → "로그인하러 가기".
- B. 만료 변경 `/expired`: 로그인 실패 응답이 "만료"(마지막 변경 후 6개월 경과)로 분류되면 진입. 현재/새/확인 입력 후 변경하거나 "다음에 변경하기"로 미루고 원래 로그인을 이어간다.
- `/main`: 레이아웃 셸이 디자인 대기라 둔 임시 메인. `/`가 여기로 랜딩한다.

## URL 계약

- `/changePw`: 쿼리스트링 없음(재설정 코드를 URL에 남기지 않는다). 라우트 가드 없음, 세션 유효성은 서버가 판단한다. 백엔드가 만든 재설정 링크로도 쓰이므로 경로 이름을 바꾸면 상대편도 수정해야 한다.
- `/expired`: 메모리에 로그인 자격 증명이 필요하다. 단 마운트 시 리다이렉트는 없다. 자격이 없으면 화면은 뜨고, 어느 버튼을 눌러도 로그인(`/login`)으로 이동한다. 새로고침하면 같은 상태가 된다.
- `/main`: `AuthGuard`(서버 `GET /sec`) 통과 필요. 실패 시 `/introduction`으로 replace.
- 두 화면의 "로그인" 목적지는 `ROUTES.login`(`/login`). 문서 title: `/changePw`는 `비밀번호 변경`, `/expired`는 `비밀번호 변경 `(끝 공백, v2와 동일).

## 제약 (코드에서 읽히지 않는 것)

- 로그인 자격 `{id,password}`는 라우터 state가 아니라 모듈 메모리에만 둔다(history/세션복원 파일에 평문 비밀번호가 남지 않게). 탭 한정, 새로고침 시 소실.
- 재로그인 `POST /login`은 **multipart/form-data**여야 한다(JSON이면 400).
- 로그인 후 랜딩은 권한으로 분기한다. MASTER/ADMIN은 SPA `/main`, 그 외는 레거시 Vue 앱 `/account`로 전체 페이지 로드(SPA 네비게이션으로는 안 됨).
- `/changePw` 5분 제한은 서버 일회용 세션의 유효시간이다. 클라이언트 타이머는 없고, 초과하면 서버가 `time out`을 반환한다. 재시도는 찾기부터 다시 한다.
- `/changePw` 성공 판정은 응답 `result === "success"`뿐이다. 그 외 2xx는 UI 변화가 없다(모달 안 뜸). `/expired`는 `result: true`.
- 에러 바디는 타입이 없으므로 `safeParse`로 읽고, 형식이 다르거나 네트워크 오류면 fallback 문구를 쓴다. 서버 메시지 필드가 다르다(`/changePw`는 `message`, `/login/expire`는 `reason`, 정확 일치·마침표 포함). 문구 매핑은 각 feature의 `lib/map-*-error.ts`.
- 비밀번호 규칙이 두 화면에서 **의도적으로 다르다**(v2 동작 유지).
  - A: 공용 `validatePassword(value, "")`. 패턴 + 4회 반복/4연속 문자 금지. id를 넘기지 않아 "아이디 포함" 검사는 서버가 한다. `maxLength=20`.
  - B: 패턴 + 화면 전용 금지어(`admin`, `concepters`, `bigbird`; 가입의 denylist와 다름). 연속/반복 검사 없음. 새 비밀번호에 `maxLength` 없음. 힌트 상수는 feature 자체 정의(값은 entities/account와 같지만 별개).
- B의 "현재 비밀번호가 아닙니다" 안내는 UX 힌트일 뿐 제출을 막지 않는다. 실제 검증은 서버(`ORIGINAL PASSWORD INVALID.`).
- 제출 불가 클릭 문구가 다르다. A는 마침표 없음, B는 있음(v2 그대로).
- 제출은 버튼 onClick이다(form 요소/Enter 제출 없음).
- 세션은 캐시하지 않는다(권한이 바뀔 수 있음). `AuthGuard`가 세션을 자식에게 넘기는 이유는 `useSession`을 또 호출하면 요청이 한 번 더 나가기 때문이다.
- `isAllowed`는 인증이 아니라 **인가 결과**다. 로그인된 사용자도 `X-Path`가 거부되면 false이고 401과 같이 처리한다. 권한 규칙은 서버가 소유하며 클라이언트는 재구현하지 않는다.
- 임시 메인은 아이디·이메일을 프로덕션 번들에 노출하지 않으려고 의도적으로 표시하지 않는다.

## 서버 에러 문구 매핑

문구 표는 `lib/map-*-error.ts`와 테스트가 기준이다. 서버 값은 정확 일치로 비교한다. `/changePw`는 `message`, `/login/expire`는 `reason`(대문자·마침표 포함 문자열 그대로)을 읽는다.

## 동작 결정

- "다음에 변경하기": 연기 API 성공 → 저장해 둔 자격으로 재로그인 → 자격은 결과와 무관하게 항상 clear. 연기 API 실패는 `잠시 후 다시 시도해주세요.`, 재로그인 실패는 `/login`.
- B 변경 성공: 자격 clear 후 전체 화면 완료 문구, "로그인하기"와 헤더 뒤로가기 모두 `/login`.
- A 완료 모달은 닫기 수단 없이 "로그인하러 가기"만 둔다. 헤더 뒤로가기는 `navigate(-1)`.
- 변경 중에는 버튼을 disabled 처리해 중복 제출을 막는다.

## v2 대비

- 만료 변경 성공 시 `clearLoginCredential()` 추가. v2는 성공 후에도 평문 비밀번호가 메모리에 남았다.
- v2의 하드코딩 `"/client"`를 `ROUTES.login`으로 대체(경로 단일 출처).
- axios 에러 캐스트를 `ApiError` + Zod `safeParse`로, React Query를 `useSWRMutation` + 응답 Zod `parse`로 교체(v2는 응답 검증 없음).
- 라우트 단일 파일을 FSD로 분리하고 `meta()`를 `<title>`로 바꿨다.
- 엔드포인트·문구·검증·금지어·이원화된 힌트는 v2와 동일.

## 범위 밖 · 미해결

- 클라이언트 5분 카운트다운, 세션 만료 사전 감지, 자격 없는 `/expired`의 마운트 시 리다이렉트: 하지 않음(미결정).
- 비밀번호 강도 미터, 6개월 판정, `/changePw`의 아이디 포함 검사: 서버 책임.
- 레거시 `/account`, 로그인 에러의 만료 분류, 찾기 인증 흐름: 각자 스펙/코드.
- i18n: `i18next` 도입 확정, 아직 미적용. 현재 한국어 하드코딩.
- 완료 화면의 중복 CTA/접근성 개선, 두 `PASSWORD_HINT` 통합: 미결.
- 서버가 실제 보내는 `reason` 전체 목록은 OpenAPI 명세 위치가 미정이라 미검증(v2 원본과만 일치).
