## 1. 목적과 시나리오

광고주가 승인되어 진행 중인 **PICK형 브랜드형** 캠페인을 가이드 작성부터 결과 확인까지 한 화면 틀에서 관리한다.

1. 현황의 "캠페인 관리" → 기본정보가 먼저 보임(명세 0001).
2. 포스팅 가이드를 쓰거나 건너뛰고, 크리에이터를 찾아 제안하고, 협상·결제로 매칭을 끝낸다.
3. 유형에 따라 배송 또는 매장 방문을 보고, 원고를 검수하고, 포스팅을 확인해 완료 승인한다.
4. 결과를 보고 크리에이터를 평가한다.

## 2. 범위

- 포함: 공통 틀·기본정보, 포스팅 가이드, 크리에이터 탐색, 크리에이터 매칭, 배송/매장 방문(유형별), 원고컨펌, 포스팅 확인, 캠페인 결과. PC·TAB·MO, 4개 언어.
- 공개(사용자 2026-11-25, 앞선 "개발 서버에서만" 변경): **stage까지 배포한다.** "캠페인 관리"·"결과 확인"의 준비 중 토스트를 없애고, 단계가 하나씩 stage에 올라간다. 아직 없는 단계는 LNB에 두고 누르면 준비 중 화면을 보인다(제안).
  - 이 저장소에는 stage와 운영을 가르는 값이 없고 `import.meta.env.DEV`(개발 서버인지)만 있다. 그래서 **운영 빌드를 만들면 그때도 열린다.** 운영 배포 전에 가릴지는 그때 정한다(P-10).
  - 지금 개발 서버에서만 켠 것: 크리에이터 매칭의 `캠페인 제안`(`IS_PROPOSAL_ENABLED`), LNB "캠페인 등록하기", AI 소개서 생성, 승인·반려 확인 버튼. 캠페인 진행 안의 제안은 stage에서도 켜야 매칭 뒤 단계를 쓸 수 있어 이 값과 따로 둔다(제안). 나머지는 바꾸지 않는다.
- 범위(사용자 2026-11-25): **브랜드형 먼저**. 공구형·모집형은 시안만 읽어 둠(로컬 `.claude/figma-cache/7553-328125/compare-types.md`). **공구샵 개설은 이번에 개발하지 않음**(사용자).
- 나중에 다시 쓰도록: 단계 구성은 유형별 배열로 두고(공구형은 원고 컨펌 없음, 모집형은 탐색·매칭 대신 모집 현황·선정), 탐색 표의 열과 제안 입력은 유형별로 바꿔 끼울 수 있게 한다(제안). 공구형·모집형 코드는 미리 만들지 않음.
- 범위 밖: 공구형, 모집형, 공구샵 개설, 구매리뷰형·구매 인증 관리(**만들지 않음**, 사용자 2026-11-25. 등록 스펙 2026-11-13 스펙아웃. 시안 LNB에 남은 "구매 인증 관리"는 잔재), 알림 발송(0137, 별도 명세), 판매·정산, 캠페인 취소·삭제·등록 정보 수정(0009), 매칭 완료 뒤 취소(0072).

## 4. 단계별 계약

각 단계의 시안 값·문구는 구현할 때 노드에서 새로 받는다(`figma.mjs outline`). 여기에는 코드·시안에서 읽히지 않는 것만 적는다.

### 1 포스팅 가이드 (`posting-guide`)

- 미작성은 `GET` 404. 방식 선택(`POST {creationMethod}`)으로 만들고, 이후 저장은 `basic-condition`·`examples` PUT이 **전체 교체**라 보내지 않은 값이 지워진다. 임시저장 전용 API는 없고 이 PUT이 곧 DRAFT 저장이다(API).
- AI 방식은 결제 또는 등록 때 구독이 있어야 한다(`payment.alreadyPaid`, 10,000원). 미결제여도 직접 작성은 됨(0021). 결제 뒤 입력값을 유지(0023).
- AI 생성 결과는 **지금 서버가 임시 문구(`[AI 생성 예정]`)를 준다**. 재생성하면 기존 내용이 덮이므로 먼저 확인받음(0025).
- 포스팅 수는 1회 고정(0018, 시안 11/19에서 입력 삭제). API 필드 `postingCount`에는 1을 보냄(제안).
- 예시 파일은 고객센터 업로드(`POST /v3/help/thread/message/{type}/{service}`)로 `attachmentIdx`를 받아 연결한다. 타임코드는 유튜브·틱톡·**인스타그램 릴스**(시안 주석 `14165:276974`, 사용자 임시 결정 2026-11-26, 대표님 확인 전). 허용 플랫폼은 상수 한 곳에 두어 릴스를 빼기 쉽게 함. 지금 서버는 유튜브·틱톡이 아니면 400이라 릴스는 서버가 풀어야 저장됨(B-13). 시안은 구간 시작·종료를 둘 다 입력하는데 API는 끝 시각(`MM:SS`) 하나만 받고 시작은 직전 구간 끝으로 계산함(B-5).
- 확정(`confirm`) 뒤에는 수정·재생성 불가(0028). 건너뛰기(`skip`)는 쓰던 내용을 지우지 않고 다시 작성할 수 있음. 건너뛰기가 성공하면 다음 진행 단계인 크리에이터 탐색으로 이동함(기록을 쌓지 않음, 기획 2026-11-27 "작성하지 않은 상태로 다음 진행 단계로 이동").
- 미리보기는 새 탭(시안: 별도 도메인, 닫기·버튼 없음). 로그인 상태로 같은 앱의 `/campaign/:campaignIdx/progress/guide/preview`를 여는 것으로 둠(제안, P-4). 저장된 값만 보여 주므로 한 번도 저장하지 않았으면 버튼을 막음(내가 정함). 미리보기의 기본 조건 카드는 시안에 제목 없는 `Title` 카드 3개(1개·5장 이상·3개 이상)인데, 포스팅 수 입력이 빠져(11/19) 사진 수·영상 수 2개만 두고 제목은 입력 화면 문구를 씀(사용자 2026-11-27, 시안 `14165:272496`). PC·TAB·MO 시안 모두 카드 제목이 `Title`, 아이콘이 지갑(wallet)인 자리 표시라, 제목은 입력 화면 문구·아이콘은 이미지·영상으로 내가 정해 올림(사용자 지시 2026-11-27). 디자이너에게 확인 요청 중이라 답이 오면 바꿈. 유의사항·참고 URL은 비었으면 행을 숨김(시안 캡션 `14165:273339`).
- 예시 탭: 콘텐츠 개요(필수 *, 300자, `PUT …/examples`)는 임시저장 때 기본 조건 다음에 저장하고, 확정 버튼은 콘텐츠 개요까지 차야 켜짐. 예시 카드(업로드·여러 장·순서·수정·타임코드)는 파일 주소(B-20)와 업로드 API(B-21) 답을 받은 뒤 붙이고, 그 전까지 탭 아래에 준비 중 표시.
- **AI 생성·AI 결제는 "준비 중"**(사용자 2026-11-26): 서버가 아직 임시 문구(`[AI 생성 예정]`)만 채우므로, AI 카드와 AI 화면 모양은 시안대로 두고 "AI 포스팅 가이드 생성하기"와 AI 결제(10,000원)는 누르면 준비 중 안내만 함. 실제 AI 연결 뒤 이 두 곳을 바꿈(B-16).
- 방식 카드(AI·직접 작성)는 시안처럼 오감. 백엔드 답(B-12): 이미 가이드가 있어도 `POST`를 다시 부르면 `creationMethod`만 바꾸고 200, 쓴 기본 조건·예시는 남음(AI로 바꿀 때는 결제 검사). 그래서 저장할 때 서버 방식과 고른 방식이 다르면 `POST`로 바꾼 뒤 저장함. AI 쪽은 준비 중이라 지금 저장이 일어나는 것은 직접 작성뿐.
- 화면 배치(사용자 2026-11-27): "이용 중"·"결제 필요" 뱃지는 PC·MO는 AI 카드 안, TAB은 카드가 좁아 제목 옆 `AI 서비스 이용 중`(시안 `14165:273751`). TAB 결제 전 상태는 시안이 없어 같은 자리에 회색 `결제 필요`(제안). 직접 작성의 패널 안 "기본 조건 설정" 제목은 바로 위 탭과 같아 모든 기기에서 뺌(MO 시안 `14165:275660`은 AI용 부품이 쓰인 것으로 봄), AI 방식 패널에는 둠.
- 확정 버튼은 필수(사진 수·영상 수·필수 키워드·필수 해시태그)가 다 차야 켜지고, 확정 뒤에는 같은 화면에서 입력이 잠김(제안, 시안 없음). 종료된 캠페인도 입력·동작을 모두 막음(REQ-14-0010).
- "가이드 확정" 알럿(제목 "포스팅 가이드 등록 완료", 취소/확인)은 **확정 전에 묻는 창**: 확인 = 확정 API, 취소 = 닫기(사용자 2026-11-26, 시안 `14165:272914`).
- 예시 제목·코멘트·타임코드를 고치는 API가 없어 "지우고 같은 `attachmentIdx`로 다시 연결"로 고침(사용자 2026-11-26). 수정 API를 요청함(B-14).

### 2 크리에이터 탐색 (`influencer-search`)

- 매칭 검색과 같은 부품. 다른 점만: 플랫폼 선택 없음(캠페인 등록 플랫폼으로 **서버가 고정**, 요청에 넣지 않음), 즐겨찾기 그룹 선택이 목록 위에 있음, 제안 대상 캠페인이 하나로 고정.
- 정렬은 팔로워 수만(API). 플랫폼별 열·숫자 표기(REQ-15-0090·0091)는 **공구형 시안에만 그려져 있어** 브랜드형에는 쓰지 않고 매칭 검색과 같게 둠(제안, P-8).
- 즐겨찾기는 매칭의 `bookmark` API를 그대로 쓰고 제안·매칭 뒤에도 유지(0038).
- 제안은 `influencer-search/proposal`(+`panel`). 한 명이라도 이미 제안했으면 **전체 실패**(API)인데 명세 0042는 "대상에서 제외"라 다름(B-6).
- Swagger 탐색 API 설명의 "캠페인 제안은 미구현"은 제안 API가 있어 낡은 문구로 봄.
- AI 추천 도우미는 매칭 검색과 같이 화면 자리만(입력 비활성).

### 3 크리에이터 매칭 (`/v3/matching/influencer/proposal*`, `campaignIdx` 필터)

- 상단 6개 집계는 `counts`(필터와 무관하게 전체 기준). "제안 발송"은 상태가 아니라 누적(0046).
- 목록 API는 쪽 나눔 없이 전체를 줌 → "N개 보기"(10·20·30)와 쪽 이동은 화면에서 나눔. 검색어(`q`)·상태(`status`)·쪽·개수는 주소 쿼리가 소유하고, 검색어·상태는 서버에 보냄(서버 필터). 새로고침은 검색·상태를 지움.
- "응답 일시" 칸은 `lastMessageAt`(마지막 메시지·상태 변경 시각, 누가 보냈든)을 씀(사용자 2026-11-27). 값이 없으면 "-".
- "남은 시간"은 `responseDeadline`까지(하루 이상이면 "N일 M시간", 아니면 "H시간 M분", 1분마다 갱신). 제안 중·재협상·결제 대기만 보이고 나머지는 "-". 보이는 줄의 기한이 지나면 목록을 다시 읽음.
- 상태 배지: 제안 중 파랑·재협상 요청 빨강·결제 대기 노랑·매칭 완료 초록·거절 회색(시안), 만료는 시안에 없어 회색(내가 정함). `NEGOTIATING`은 광고주가 다시 제안해 크리에이터를 기다리는 때도 같은 값이라(B-7 답), 목록의 `awaitingResponseFrom`(B-23 답)이 `INFLUENCER`면 "제안 중"(파랑)으로, `ADVERTISER`면 "재협상 요청"으로 보임. 상태 필터 "재협상 요청"·"제안 중"은 서버 `status` 값으로 거르므로 이 구분과 어긋날 수 있음(서버 필터 그대로 둠).
- 체크박스는 결제 대기 줄만 켜지고, 머리글 체크는 지금 쪽의 결제 대기 줄 전체. 종료 캠페인은 체크·결제 버튼을 막음. 결제하기·일괄 결제는 결제 MR(C) 전까지 준비 중 안내.
- 서버 상태 → 화면 6종: 제안 중 `PROPOSED`, 재협상 요청 `NEGOTIATING`, 결제 대기 `ACCEPTED`, 매칭 완료 `PAID`, 거절 `REJECTED`, 만료 `EXPIRED`. 광고주가 다시 제안해 상대 응답을 기다리는 때도 "제안 중"이어야 하는데(0049) 서버가 어느 값을 주는지 확인 필요(B-7). `CONTENT_CONFIRM`은 "현재 어떤 제안도 되지 않는 값"(API)이라 모르는 값과 같이 다룸.
- 기한: 최초 5일, 재협상 2일, 수락 뒤 결제 72시간. 재협상은 양쪽 합산 최대 3회이고 3회 뒤 "다시 제안"을 끔(0052~0059). 남은 시간은 서버 기한으로 계산하고 0이 되면 목록을 다시 읽음.
- 결제 금액은 **서버 `payment/preview` 값만 표시**한다(프론트에서 수수료·VAT를 계산하지 않음, 명세 0064는 요율 미정이고 API는 5%·수수료에만 VAT).
- 결제 안내의 "공구 수수료는 추후 공구가 종료된 후…" 줄은 **브랜드형에서 제외**(사용자 2026-11-25). 캠페인 상세 `productType`이 `GROUP_BUY`일 때만 보인다. 시안에는 브랜드형에도 있음(`13709:295039` 등).
- 결제 선택은 결제 대기 행만. 하나라도 결제 대기가 아니면 전체 실패하고 부분 결제는 없음(API). 실행 직전 다시 조회해 만료된 대상을 뺌(0063).
- 원고컨펌이 켜져 있으면 1인 5,000원이 더해짐(0065). 미리보기 응답에 포함되는지 확인(B-8).
- 잔액이 모자라면 충전(최소 100,000, 최대 100,000,000) 뒤 같은 결제 화면으로 돌아옴(0067·0069).
- **매칭 상세보기**(매칭 내역 토글): PC는 오른쪽 드로어(폭 810, 대화 + 크리에이터 정보 두 열), TAB·MO는 목록 자리를 덮는 전체 화면에 "크리에이터 채팅 / 크리에이터 정보" 탭(시안 `13709:294810`·`291940`·`293150`). 대화창 위에 "캠페인 제안 및 협상 단계" 안내를 붙여 둠.
  - 대화는 `GET .../messages` 전체, 삭제된 메시지는 뺌. 지금 라운드 카드(`proposalCard`) 하나를 대화 끝에 둠. 시안은 라운드마다 카드가 대화 사이에 있지만 지난 라운드 값이 API에 없음(B-25).
  - 카드 배지는 `status`로 정함(`tag` 한국어 문구는 쓰지 않음, B-27). 수수료는 공구형(`groupBuyFeeRate` 있음)만.
  - 수락·거절·다시 제안 버튼은 크리에이터가 재협상을 요청해 광고주 차례일 때(`NEGOTIATING` + `ADVERTISER`)만, 종료 캠페인은 숨김. 수락 → "제안 수락 확정" → 성공하면 "이어서 결제 진행"(나중에 결제 = 닫기, 지금 결제하기 = 결제 MR 전까지 준비 중). 거절은 확인 창 뒤 요청. 다시 제안은 대화창 아래 금액 입력(희망 업로드 일정은 시안에 없어 보내지 않음 → 서버가 이전 값 유지). 남은 재제안 횟수는 서버가 409로 막음(횟수 표시는 B-28).
  - 409(이미 처리·차례 아님·캠페인 기간 종료 B-4)는 안내 후 대화·목록을 다시 읽음. 지금은 인플루언서 응답 API가 없어 수락·거절·다시 제안이 항상 409(Swagger).
  - 크리에이터 정보: `GET .../info`. 캠페인 이미지·SNS 채널 주소는 API에 없어 이미지 칸은 빈 회색, 채널 버튼은 꺼 둠(B-26). 진행 상태는 서버 한국어 문구 그대로(코드 요청 B-27).
  - 메모는 입력이 0.8초 멈추면 전체를 저장(`PUT .../memo`, 최대 2000자). 창을 닫을 때 남은 입력도 저장. 실패하면 칸 아래에 안내.
  - 내 메시지 이름은 로그인 계정 표시 이름(시안 "광고주명").
- 채팅은 LNB 채팅과 **같은 대화방**. 매칭 완료 전에는 카드만, 자유 입력은 `PAID`부터. 대화 조회가 곧 읽음 처리(API).

### 4 배송 / 매장 방문 (`delivery` · `store-visit`)

- 매칭 완료(`PAID`)만 나옴. 매장 방문은 **조회 전용**이고 기록이 없으면 방문 예정으로 옴.
- 송장 등록·수정은 같은 PUT. 택배사는 `GET /shop/courier`의 `name`을 그대로 보냄. 배송 상태는 이 API가 바꾸지 않음.
- 전체 배송 명단·송장 양식·송장 업로드 버튼은 **보이되 비활성**(사용자, V3 API 없음).
- 목록 조회 실패와 배송 조회 불가를 구별: 송장값은 남기고 상태만 안내(0080).

### 5 원고 컨펌 (11/25 시안 편집기 방식, 사용자)

- **메뉴는 항상 보임**(기획 답 2026-11-26). 미신청이면 시안대로 미신청 화면(카드 값 "-", 부가서비스 결제하기, REQ-14-0115). 신청 여부는 `GET …/manuscript`의 `addOnApplied`(느낌표 `needsAttention`도 같은 응답). 미신청이면 느낌표 없음(REQ-14-0008).
- 미신청 캠페인의 신청 안내·추가 신청·결제(시안 11/16, REQ-14-0088~0095·0115·0116, `addon-preview`·`addon-apply`)는 원고 컨펌 메뉴의 미신청 화면에서 들어감(메뉴가 항상 있으므로 범위에 넣음, 기획 답 2026-11-26).
- **기준 API는 `/posting`**(목록·본문·이미지·영상·메모·채팅·수정 요청·승인). AI 컨펌은 `/manuscript/{proposalIdx}/ai-feedback`뿐인데 **`/posting` 목록에 `proposalIdx`가 없다**(B-1, 막힘).
- 본문·이미지·영상·메모의 **응답 형태가 Swagger에 없다**(B-2, 막힘). 목록만 먼저 만들 수 있음.
- 상태 6종(`NONE`·`CHECK`·`PROCEEDING`·`EDITING`·`APPROVAL`·`COMPLETE`)과 명세·시안의 4종(미제출·미검수·수정 중·승인 완료) 대응은 확인 필요(B-9).
- "수정 완료"가 곧 수정 요청이고 되돌릴 수 없음. 승인 뒤 수정·승인 취소 없음(0107). 승인돼야 크리에이터가 포스팅을 등록할 수 있음.
- 편집기에서 나갈 때 바뀐 것이 있으면 알럿, 없으면 바로 이동(시안 `14597:281018`). 메모는 **계정 전체 공용**(캠페인과 무관, API).
- 편집기 라이브러리는 정하지 않음(P-5). 저장 형식(HTML인지)을 알아야 고를 수 있고, HTML이면 표시 전 정화가 필요.
- AI 컨펌은 지금 서버가 고정 문구를 준다.

### 6 포스팅 확인 (`posting-confirm`)

- 한 줄 = 크리에이터 1명. PICK형은 회차 1개라 펼침 없이 보임(`totalRounds`).
- 완료 승인은 **되돌릴 수 없음**(0114) → 확인 알럿. `postingMapIdx`가 null이면(URL 미등록) 승인할 수 없음.
- "포스팅 확인"은 `canOpenPosting`일 때만 새 창. 문의는 5단계와 같은 통합 채팅.

### 캠페인 결과 (`result`)

- 탭: 요약 / 대표 포스팅 / 크리에이터별 성과. 승인 0건이면 409.
- 지표 null은 `-`, 실제 0은 `0`(0127·0134).
- 진입 때 저장된 값을 먼저 보이고 마지막 수집이 1시간 넘었으면 갱신(0133). 수집 시각·갱신 요청 API가 안 보임(B-10).
- 평가는 별점 1~5 + 피드백 300자(선택), 크리에이터당 캠페인별 1번, 수정·삭제 불가. 등록 뒤에는 별점을 눌러 조회만.

- 코드로 받아 번역: 배송(`NOT_SHIPPED`·`PREPARING`·`IN_TRANSIT`·`DELIVERED`), 방문(`SCHEDULED`·`COMPLETED`), 원고 6종, 포스팅(`WAITING`·`REGISTERED`·`APPROVED`), 가이드(`DRAFT`·`CONFIRMED`·`SKIPPED`), 제안 상태. 시안 문구는 구현 때 노드에서 확인하고, 모르는 값은 서버 값 그대로 표시
- 그대로 표시: 택배사 이름, 협찬 제품명, 카테고리
- 시안에 없는 문구(제안): 409 공통 "다른 곳에서 먼저 처리되었습니다. 최신 상태로 다시 불러왔습니다." / 종료 거절 "종료된 캠페인에서는 할 수 없는 작업입니다." / 검색 0건 "검색 결과가 없습니다."
- 숫자·금액·일시·남은 시간은 공용 포맷 함수

## 9. 종단 간 검증

- stage 배포 뒤: 만든 단계가 열리고 없는 단계는 준비 중으로 보임
- `pnpm verify`, `pnpm build`, 단계마다 시안 대조(`design-qa` 도구, 스크롤바를 숨기지 않음, 실제 데이터로 행이 많은 경우 포함)
- 유형 3개(제품발송·매장방문·기자단)에서 LNB 단계 수, 없는 단계 주소로 직접 진입
- 종료 캠페인: 모든 단계 조회, 동작만 비활성, 결과는 맨 아래 메뉴로, 승인 0건이면 빈 상태
- 가이드: 미작성(404) → 건너뛰기 → 다시 작성 → 확정 뒤 수정 불가
- 매칭: 결제 대기만 선택, 잔액 부족 → 충전 → 복귀, 결제 중 두 번 누르기, 72시간 만료
- 원고컨펌 등록 캠페인만 LNB에 보이고, 미등록이면 주소로 와도 기본정보로 감, 포스팅 승인 확인 알럿과 되돌리기 없음
- 결과 지표 null은 `-`, 0은 `0`
- 결제·제안·승인처럼 stage 데이터가 바뀌는 확인은 사용자 지시가 있을 때만
