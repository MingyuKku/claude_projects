> 6번(등록 중 캠페인)·7번(진행 중 캠페인) 탭은 지금 시안과 다른 옛 화면 구성(별도 목록·상태 필터·"완료된 캠페인" 영역)을 설명하므로, 시안에 없는 정보(삭제 확인 문구 등)를 보충할 때만 씁니다.
> 화면별 문구 원문·디자이너 주석·node 대응은 로컬 캐시에 있습니다(로컬 전용): `.claude/figma-cache/campaign.md`(시안), `req-campaign-status-v2.md`(4·5번 탭 개정판 원문, 이 문서의 REQ-4·5 번호는 여기서 찾습니다), `req-campaign-status.md`(2026-11-10 옛 판 4~7번, 6·7번 탭 참고용).
> 8단계 등록 마법사와 등록 내역은 [register](./register.md)가 기준입니다. 이 문서는 그 앞(개설)과 바깥(현황 목록)만 다룹니다.

## 1. 목적과 범위

- 광고주가 **자기 캠페인을 진행 단계별로 모아 보고**(현황), 새 캠페인을 만들 때 **서비스와 상품을 고른 뒤 등록 마법사로 들어갑니다**(개설).
- 용어: **개설**은 서비스(모집형/PICK형)와 상품(브랜드형/공구형)을 고르기만 하는 화면이고 저장하는 것이 없습니다. **등록**은 고른 유형으로 내용을 쓰고 결제해 승인을 요청하는 8단계 마법사(`/campaign/register`)입니다. 시안은 개설 화면의 섹션 제목과 진입 버튼을 "캠페인 등록"이라고 부르지만, 문서와 코드에서는 둘을 구분합니다.
- **API는 아직 구현 전입니다.** 등록처럼 목 데이터로 동작합니다. 목록·삭제는 백엔드가 [캠페인 등록 API 요구 명세](https://claude.ai/artifact/UGv9ZruAw7qhJyzQopAHfU)에 함께 넣었습니다(2026-11-12: 목록 A-2, 삭제 A-4). 그래서 따로 만들려던 "캠페인 현황 API 요구 명세"는 만들지 않고, 현황에 필요한 응답 필드는 그 문서 A-2에 프론트 요청으로 적었습니다(§5). 개설의 구독 상태만 실제 구독 API(`entities/subscription`)를 씁니다.
- **두 화면 모두 개발 서버에서만 동작합니다.** stage·prod 빌드에서는 등록처럼 `coming-soon`이고, 진입점(LNB "캠페인"·"캠페인 등록하기", 홈 "캠페인 등록/운영" 카드)도 개발 서버에서만 켭니다(사용자 결정). 캠페인 기능 전체를 한 번에 공개하기 위해서입니다.

| 진입점 | 도착 |

### 시나리오

1. LNB "캠페인"으로 들어오면 전체 탭이 열립니다. 탭(전체·등록 중·승인 대기/반려·진행 중·종료), 캠페인 유형 필터, 캠페인명·브랜드명 검색으로 목록을 좁힙니다. PC·TAB은 페이지 번호, MO는 끝까지 스크롤하면 다음 쪽을 불러옵니다.
2. 행의 바로 가기로 이어서 작업합니다. 등록 중은 "작성하기"로 등록 마법사(작성 완료한 데모는 "등록 내역"), 승인 대기는 "등록 내역", 승인 반려는 "반려 사유"로 등록 내역(`/campaign/:campaignId`, 보완 요청 메시지가 보임)으로 갑니다. 승인 대기·승인 반려·진행 중·종료의 오른쪽 문서 아이콘도 등록 내역(기본 정보)으로 갑니다. "캠페인 관리"·"결과 확인"은 캠페인 진행 화면(범위 밖)이라 준비 중 토스트만 띄웁니다.
3. 등록 중 캠페인(데모 포함)은 휴지통 아이콘으로 지웁니다(확인 알럿 → 삭제 → 목록 갱신). 승인 대기·승인 반려는 지울 수 없고, 등록 내역에서 승인 요청을 취소해 등록 중으로 돌린 뒤 지웁니다(REQ-5-0033).
4. "+ 캠페인 등록하기"로 개설에 오면 서비스 카드 4개(모집형·PICK형·라이브형·어필리에이터형)가 보입니다. 구독 중인 서비스 카드를 누르면 아래에 그 서비스의 상품 카드(브랜드형·공구형)가 나오고, **브랜드형 카드를 누르면** `/campaign/register?type=recruit|pick`으로 갑니다.
5. 구독하지 않은 서비스는 "구독하기"로 마이페이지 구독에 가거나, "데모 체험하기"(또는 카드 자체)로 데모 상품 카드를 볼 수 있습니다. 데모는 횟수 제한 없이 여러 개 만들 수 있고, 구독 중인 서비스에는 데모 경로가 없습니다(REQ-4-0010·0022). PICK형 "데모 캠페인 등록"은 등록 마법사의 데모 모드로 갑니다([register](./register.md) §3 데모 모드, 사용자 결정 2026-11-12). 모집형 데모 캠페인 등록과 공구형은 준비 중 토스트입니다.

### 범위 안 화면

| 경로 | 화면 |
|---|---|
| `/campaign` | 현황. 탭·필터·검색·페이지는 쿼리(`?tab=&type=&q=&page=`)로 두어 새로고침·뒤로가기·공유에도 유지합니다 |
| `/campaign/new` | 개설. 고른 서비스는 쿼리(`?service=recruit\|pick`)로 둡니다 |

`/campaign/new`는 기존 `/campaign/:campaignId`(등록 내역)와 겹쳐 보이지만, React Router는 고정 경로를 동적 경로보다 먼저 맞춥니다.

## 2. Figma 기준 노드

화면·상태별 노드 ID(PC 1440 · TAB 768 · MO 360)는 `.claude/figma-cache/campaign.md`에 있습니다. 캔버스는 가로로 "캠페인 현황"(x 3759~12377)·"캠페인 개설"(x 13101~18473) 두 구역입니다.

- 프레임 이름은 믿지 않습니다. 개설 프레임과 일부 MO 현황 프레임이 모두 `… / Campaign Registration`이고, MO 필터 화면은 `MO / Subscribe`입니다. 구역 제목과 화면 내용으로 구분합니다.
- `Guide Caption/Inform`은 디자이너 주석입니다. 개설 시안의 숨은 보조 문구 "LNB에서 빅버드 문의 클릭 시…"는 다른 화면에서 복사된 잔재라 따르지 않습니다.
- 시안끼리 다르면 **PC 시안**을 따르고 차이는 §8 디자인 요청에 모읍니다(등록 스펙 D-10과 같은 기준).

| 빈 상태 | 탭·툴바는 그대로 두고 세 경우로 나눕니다(REQ-5-0030~0032, 문구 §6). ① **계정에 캠페인이 하나도 없음**(전체 탭 + 검색어·필터 없음 + 0건): 가운데 아이콘 + "등록된 캠페인이 없습니다." + 안내 + **"캠페인 등록하기"** 버튼(개설로 이동). ② **상태 탭에 없음**: 표 안에 아이콘 + 탭별 문구(진행 중 탭은 시안 "진행 중인 캠페인이 없습니다."), 버튼 없음. ③ **검색·필터 결과 없음**: 검색어가 있으면 "'{검색어}'에 대한 결과가 없습니다."(시안), 필터만이면 조건 결과 없음 문구, 둘 다 검색·필터를 바꾸라는 안내, 버튼 없음. ①·② 탭별·③ 필터만 문구는 시안이 없어 D-5 |
| 불러오기·오류 | 처음 불러오는 동안 행 자리 스켈레톤(`skeleton-presets`), 실패하면 기존 목록 오류 패턴(다시 시도)입니다. 시안 없음 |

| 항목 | 결정 |
|---|---|

| 구독 상태 | `entities/subscription`의 구독 목록으로 판단합니다(`getSubscribedTypes`, 해지 예정·결제 실패도 구독 중으로 보는 기존 기준). 구독 중이면 비활성 모양의 "서비스 이용 중"(명세의 "이용 중"은 시안 문구로), 아니면 "데모 체험하기 >" + "구독하기"입니다. 모집형·PICK형 구독은 따로 판단하고 둘 다 이용 중일 수 있습니다(REQ-4-0005). 구독 중일 때 "데모 체험하기"는 **PC 시안대로 숨깁니다**(REQ-4-0010·0022와 같음, TAB·MO 시안은 보임 → D-7). **구독이 만료되면 미구독과 똑같이** 보입니다(REQ-4-0020). 화면에 들어올 때마다 구독 목록을 다시 읽어(SWR 마운트 재조회) 구독하고 돌아오면 바로 반영합니다(REQ-4-0002·0012). 구독 목록을 못 불러오면 모두 미구독으로 보여 주지 않고 오류 안내를 띄웁니다 |
| 서비스 선택 | 모집형·PICK형 카드를 누르거나 "데모 체험하기"를 누르면 그 카드가 선택(파란 테두리)되고 아래에 "캠페인 상품 선택" 섹션이 나옵니다. 선택은 `?service=recruit\|pick`입니다. 처음 들어오면 선택 없음이고 상품 섹션이 없습니다(`9853:935165`). LNB·현황의 "캠페인 등록하기"는 쿼리 없이 `/campaign/new`로 가므로 다시 들어오면 선택이 풀리고(REQ-4-0002 "재진입 시 서비스·데모 선택 초기화"), 새로고침·뒤로가기는 쿼리로 유지합니다. **미구독 카드 자체를 눌러도 "데모 체험하기"와 같이** 데모 상품 카드가 나오고, 실제 등록 상품은 보이지 않습니다(시안 주석 "구독이 필요한 서비스 클릭 시", REQ-4-0011). "이용 안내"("데모 체험은 무제한으로 이용 가능합니다." / "캠페인 등록은 해당 구독 상품을 구독해야 진행할 수 있습니다.")는 늘 맨 아래에 있습니다 |
| 상품 카드 | 선택한 서비스 이름(파랑) + "브랜드형"/"공구형" + 설명 4줄입니다. 설명은 시안 문구 그대로입니다. 개정 명세서(REQ-4-0015~0018)는 서비스별 설명을 새로 정했는데(모집형 = 공개 모집·신청자 선정, PICK형 = 직접 탐색·제안, "원고 AI 컨펌(건당 5,000원)" 대신 "원고컨펌". 명세의 "구매리뷰형 진행" 안내는 2026-11-13 스펙아웃으로 넣지 않음) 시안은 옛 문구라 D-8로 정정을 요청합니다. **구독 중 서비스**: 버튼 없이 카드 전체가 버튼이고(명세 REQ-4-0014의 "캠페인 등록하기" 버튼은 시안을 따라 두지 않음), 브랜드형은 `/campaign/register?type=<service>`, 공구형은 준비 중 토스트입니다. **미구독 서비스**: 카드마다 "데모 캠페인 등록 >"이 있습니다. PICK형 브랜드형은 `/campaign/register?type=pick&demo=true`(데모 모드, 사용자 결정 2026-11-12), 모집형·공구형은 준비 중 토스트입니다(모집형 데모는 모집형 갱신 때, register P-28) |
| 구독하기 | `/mypage/subscribe`로 갑니다(REQ-4-0011·0012). 해당 상품을 미리 고른 상태로 열지는 않습니다(구독 화면에 그런 진입이 없음) |

| 등록 진입 권한 | 로그인한 광고주만 들어옵니다. 비회원은 기존 세션 middleware가 로그인으로 보냅니다(REQ-4-0003). 이 앱은 광고주 계정 전용이라 명세 REQ-4-0004의 "인플루언서 모드"는 해당이 없습니다(PRD에 모드 개념 없음). 서버는 캠페인 생성·저장 때 구독을 검사하지 않고 결제 때만 검사하므로(API A-1·A-9), 미구독·만료 서비스의 실제 등록 진입은 이 화면(구독 상태)과 현황 "작성하기"(P-5)가 막습니다(REQ-4-0019·0020) |
| 구독 만료 뒤 등록 중 캠페인 | 만료된 서비스의 등록 중 실제 캠페인은 입력값을 보존하되 **수정 진입을 막습니다**(REQ-4-0020). 현황 "작성하기"를 누르면 그 서비스 구독을 확인해, 없으면 이동하지 않고 구독 안내 알럿(문구 §6, "취소" · "구독하기")을 띄웁니다(P-5). 데모 캠페인은 제외입니다 |

## 5. 데이터 흐름의 예외

- **API 없음 → 목.** 등록과 같은 방식입니다. `entities/campaign/api` fetcher가 개발 서버에서 목 모듈로 응답하고, 목 응답도 Zod로 검증합니다. 아래는 캠페인 등록 API 요구 명세의 목록 A-2·삭제 A-4와 현황용 프론트 요청 필드를 정리한 것입니다(§1).
  - **목록** `GET /v3/campaign`(API A-2): 탭은 `status`로 보냅니다. 전체 = 없음, 등록 중 = `DRAFT`, 승인 대기/반려 = `REVIEWING,REJECTED`, 진행 중 = `IN_PROGRESS`, 종료 = `ENDED`. 유형 필터는 `serviceType`(`PICK`·`RECRUIT`) + `productType`(`BRAND`·`GROUP_BUY`), 검색은 `keyword`(캠페인명·브랜드명, REQ-5-0005), 쪽은 `page`·`entrySize=6`. 응답은 `{list, count, currentPage, entrySize}`이고 항목은 `campaignIdx`·`campaignCode`·`serviceType`·`productType`·`status`·`name`·`brandName`·`campaignType`·`platform`·`createdDate`입니다. **현황에 더 필요해 요청한 필드**: `description`(부제, REQ-5-0011)·`thumbnailUrl`(5단계 메인 이미지)·`startDate`·`endDate`(승인 전은 희망 일정)·`demo`·`demoCompleted`. 정렬은 최초 등록일 최신순 + 고정 보조 기준(REQ-5-0013, 요청). 계정 전체 0건은 조건 없는 전체 조회의 `count=0`으로 판단합니다.
  - **삭제** `DELETE /v3/campaign/{campaignIdx}`(API A-4): 등록 중(`DRAFT`)만, 데모 포함. 아니면 `409 NOT_DELETABLE`(토스트 후 목록 다시 읽기), Sub ID는 `403`.
- **진행 단계는 서버 `status`로 정합니다.** 코드는 `DRAFT`·`REVIEWING`·`REJECTED`·`IN_PROGRESS`·`ENDED`이고(API 코드 표, 등록 상세와 같은 값) 화면 배지는 등록 중·승인 대기·승인 반려·진행 중·종료입니다. 진행 중·종료는 서버가 승인 여부와 종료일로 나눠 주므로 프론트가 날짜로 계산하지 않습니다. 모르는 코드가 오면 배지는 서버 값 그대로, 바로 가기는 등록 내역으로 둡니다. (전에 따로 받으려던 목록 전용 코드 `PENDING`과 `tab` 파라미터는 쓰지 않습니다.)
- **API에서 확인할 것**: 위 요청 필드(부제·썸네일·기간·데모)를 목록 응답에 넣어 주는지, 승인 전 기간을 구분하는 값이 필요한지(P-6). 해소: 종료 판정(서버 `status`, REQ-5-0029), 정렬(최초 등록일 최신순), Sub ID는 배정된 캠페인만 받음(API A-2 접근 규칙).
- **목 데이터**: 등록 마법사와 **같은 목 DB**(메모리 + `sessionStorage`)에서 목록을 만듭니다. 마법사로 만든 캠페인이 바로 목록에 나오고, 삭제하면 마법사에서도 사라집니다. 마법사로는 진행 중·종료를 만들 수 없어서 시드 데이터로 진행 중·종료 캠페인을 몇 개 넣습니다(승인 완료 = 진행 중). 목도 서버처럼 `status`·유형·검색(캠페인명·브랜드명)·쪽(6개)을 걸러서 최초 등록일 최신순으로 줍니다. 데모 캠페인도 같은 목 DB에 데모 표시와 함께 들어갑니다.
- **목록 조회 훅이 둘입니다.** PC·TAB(쪽 이동)은 `?page=` 한 쪽을 읽는 SWR, MO(이어 읽기)는 기존 `useInfinitePages`입니다. 빅버드 머니 내역처럼 `useMediaQuery`로 고르고, 화면 폭이 바뀌면 다른 훅으로 갈아탑니다.
- **캐시 갱신**: 삭제 뒤에는 목록 키 전체(모든 탭·쪽)를 키 매처로 다시 읽습니다. 등록 마법사·등록 내역에서 상태를 바꾼 뒤 현황으로 돌아오면 목록이 마운트될 때 다시 읽으므로 따로 비우지 않습니다. 삭제한 캠페인의 등록 초안·내역 캐시는 지웁니다.

  1. LNB "캠페인"·홈 카드 → `/campaign` 전체 탭, LNB "캠페인 등록하기"·현황 "+ 캠페인 등록하기" → `/campaign/new`인지 봅니다. stage·prod 빌드에서는 두 경로가 준비 중 화면이고 진입점이 비활성인지 확인합니다.
  2. 탭마다 해당 진행 단계만 나오고(전체는 모두, 데모는 전체·등록 중), 탭을 바꾸면 쪽이 1로 돌아가고 검색어·유형이 유지되는지, 새로고침·뒤로가기에 탭·검색·유형·쪽이 유지되는지, 초기화 아이콘이 탭은 두고 검색어·유형만 비우는지, 캠페인명·브랜드명으로 검색되는지, 한 쪽 6개·최초 등록일 최신순인지 봅니다. 잘못된 `tab`은 전체 탭입니다.
  3. 배지 5종 색·문구, DEMO 태그, 상태별 바로 가기·아이콘(§3 표)과 이동 경로를 확인합니다. "작성하기"는 첫 미완 단계로(데모는 데모 모드로), 작성 완료 데모의 "등록 내역"은 데모 안내가 있는 기본 정보로, "반려 사유"는 보완 요청 메시지가 보이는 등록 내역으로 열립니다. 구독이 만료된 서비스의 실제 등록 중 캠페인 "작성하기"는 구독 안내 알럿을 띄웁니다. "캠페인 관리"·"결과 확인"은 준비 중 토스트입니다.
  4. 등록 중 삭제(데모 포함): 알럿 → 삭제 → 목록에서 빠지고 토스트, 같은 캠페인의 작성 주소가 더 이상 열리지 않고 이전 캠페인 불러오기 목록에서도 빠지는지 봅니다. 승인 대기·반려·진행 중·종료에는 휴지통이 없고 문서 아이콘입니다.
  5. 빈 상태 세 가지(계정 0건은 "캠페인 등록하기" 버튼, 탭별 문구, 검색·필터 결과 없음은 버튼 없음), 불러오기 실패(다시 시도), 0건이면 쪽 이동이 숨는지 봅니다.
  6. TAB 2열 카드 + 쪽 이동(아이콘이 바로 가기 왼쪽), MO 1열 카드 + 이어 읽기 + "필터" 화면(`?panel=filter`, 초기화·적용하기, 뒤로가기로 닫힘), MO는 모든 탭에 "+ 캠페인 등록"이 있는지 봅니다. 화면 폭을 바꿔도 목록이 깨지지 않는지 봅니다.
  7. 등록 마법사에서 새로 만든 캠페인이 현황 등록 중 탭에 바로 나오고, 결제 후 승인 대기로, 개발용 전환 버튼으로 반려·승인 완료(진행 중)로 바뀌는지 봅니다.
  8. 개설: 구독 없음(서비스 카드만 + 이용 안내), 구독 중 서비스(PC는 "서비스 이용 중"만, 카드 선택 → 상품 카드, 브랜드형 클릭 → `/campaign/register?type=`), 미구독 서비스("데모 체험하기"·카드 선택 → 상품 카드에 "데모 캠페인 등록" → PICK형 브랜드형은 데모 모드 등록 마법사, 모집형은 준비 중 토스트, "구독하기" → `/mypage/subscribe`), 공구형 → 준비 중 토스트, 라이브형·어플리에이터형 무반응, `?service=` 새로고침 유지, 구독 정보 실패 안내를 확인합니다.
  9. Sub ID: 현황은 버튼 3종(등록하기·작성하기·휴지통)이 숨고 등록 내역 이동은 되는지, `/campaign/new`는 계정 설정으로 보내지는지 확인합니다.
