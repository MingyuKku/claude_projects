# 메인 · 공통 헤더와 좌측 LNB

## 경로와 접근

- `/`: 로그인·비로그인 모두 접근 가능한 홈(`pages/home`의 `HomePage`, 본문은 [home.md](home.md)). 라우트 loader가 이동할 때마다 `GET /v3/sec`에 `X-Path: /`를 보내고, 결과를 기다리지 않고 넘긴 Promise로 `SessionAppShell`이 헤더 상태를 정한다. 401이어도 홈에 머물고 외부 `redirectTo`는 사용하지 않는다. 인증이 필요한 후속 화면은 라우트의 세션 middleware로 보호한다.
- `/main`: 이전 주소 호환용. 쿼리를 유지하며 `/`로 replace 이동한다.
- 로그인 성공 후 목적지는 권한·로그인 방식과 관계없이 `/`.
- 공개 소개는 `/introduction`에 있다.
- `/influencers/search`: 홈 검색의 이동 대상인 임시 "준비 중" 화면(`pages/coming-soon`). 로그인 여부와 관계없이 접근하고 셸 안에 표시한다. 세션 조회·로딩·오류 처리는 `widgets/app-shell`의 `SessionAppShell`로 홈과 함께 쓴다.

## 디자인과 구성

공통 셸은 기존 `AppHeader`, `SidebarNav`, `UserMenu`, `Sheet`를 `widgets/app-shell`에서 조합한다. 기준 Figma 파일은 `k5VBKeB2apb3wb4l4Af3sZ`이며 PC 셸 `5202:101654`, 태블릿 `6785:18961`, 모바일 메뉴 `6791:55851`을 대조했다.

- PC(1440px 이상): 230px 좌측 LNB, 접으면 56px 레일. **기본은 펼친 사이드바**이다(사용자 결정 2026-11-10: 접힘 여부는 기억하지 않고 새로고침하면 항상 펼침. 이전 디자인팀 QA 2026-10-28 "모든 LNB는 closed 상태를 Default로"를 대체). 헤더 64px.
- 태블릿(768px 이상): 56px 레일과 64px 헤더. 레일의 메뉴 버튼으로 전체 메뉴를 연다.
- 모바일: 52px 헤더와 메뉴 버튼. 펼침 메뉴는 230px(PC 사이드바와 같은 폭, 홈 시안 `6879:33411`)이며 배경을 가린다.
- 전체 메뉴는 닫기·배경 클릭·Escape로 닫고, 메뉴 항목을 고르면 이동이 끝날 때 닫는다(이동하는 동안은 열어 두어 아래 이동 중 표시가 보이게 함). 닫으면 열었던 버튼으로 포커스가 돌아간다.
- 메뉴를 누르면 세션 확인이 끝날 때까지 이전 화면에 머물므로, 누른 메뉴에 이동 중 표시(shadcn `Spinner`)를 한다. 1차 메뉴·레일은 아이콘 자리, 아이콘이 없는 하위 메뉴는 이름 오른쪽. 시안이 없어 레이아웃이 변하지 않는 자리에 둔 임시 표현이다.
- 로그인 헤더는 포인트·알림·프로필을 표시하며 프로필은 실제 세션의 사용자명·이메일을 사용한다.
- 비로그인 헤더는 Figma `5180:89060` 기준으로 이용 가이드와 로그인 버튼을 표시한다. 로그인 버튼은 현재 앱의 `/login`, 가이드는 기존 노션 문서를 새 탭으로 연다.
- 본문은 로그인 여부와 관계없이 항상 보여 주고, 세션 조회 결과는 헤더·LNB 모양만 정한다(`SessionAppShell`).
  - 확인 중: 화면 전체를 **비로그인 UI(기본값)** 로 그리고 그 위에 전체를 덮는 밝은 오버레이(`bg-background/70`)와 스피너(`role="status"`)를 얹는다. 확인이 끝나면 로그인이면 로그인 UI로 바뀌고 401이면 비로그인 UI 그대로다.
  - 다시 확인하는 동안(다시 시도, 홈 ↔ 검색 이동)은 직전 결과로 그리고 오버레이를 띄우지 않는다.
  - 401이 아닌 통신·검증 오류: 본문과 비로그인 UI는 그대로 두고 토스트("로그인 상태를 확인하지 못했습니다. 다시 시도해 주세요." + 다시 시도 버튼)로 알린다. 백엔드가 없는 로컬 개발에서도 홈이 보인다.
- 이용 가이드는 기존 광고주 앱과 동일한 [노션 가이드](https://app.notion.com/p/3d18da2cf42f807a8535dc57072dfd10?source=copy_link)를 새 탭으로 연다. **비로그인이면 헤더에만, 로그인이면 펼친 LNB 하단에만** 둔다(Figma 주석 `5180:89119`: "유저 로그인 시 이용 가이드 버튼 헤더에서 LNB 하단으로 이동").
- PC(1440 이상) 사이드바의 접힘 여부는 Zustand 스토어(저장하지 않음)로만 들고 있어, 새로고침하면 항상 펼친 상태로 시작한다. 태블릿 레일과 전체 메뉴(Sheet)에는 적용하지 않는다.
- 로그인 판단은 `session.isAllowed`일 때만 로그인 헤더다. `result: false`(경로 권한 거부)는 비로그인처럼 처리한다.

## 현재 구현 범위

- 펼친 LNB의 빅버드 로고는 **ADMIN이면 `/a/change` 아이디 변경 화면([상세](auth/switch-account.md)), 그 외 권한·비로그인이면 홈(`/`)** 으로 이동한다. 접근성 이름도 권한별로 나눈다("빅버드 · 아이디 변경" / "빅버드 · 홈"). 전체 메뉴(`Sheet`)에서 누르면 메뉴가 닫힌다.
- 홈 링크, LNB 접기·펼치기, 모바일 전체 메뉴, 프로필 드롭다운을 지원한다.
- 펼친 LNB의 하위 메뉴 그룹은 **모두 접힌 상태가 기본**이고(이전의 고객센터 항상 펼침 제거), 현재 화면이 하위 메뉴인 그룹만 펼쳐 위치를 보여 준다(디자인팀 QA 2026-10-28).
- 펼친 LNB의 메인 메뉴는 **210×40**, 서브 메뉴는 **177×32**이다(디자인팀 QA 2026-10-28, Figma `5052:72938`). 사이드바 폭 230px에서 안쪽 여백 10px을 뺀 값이므로 오른쪽 선을 `border`가 아니라 안쪽 그림자로 그려 레이아웃 폭을 1px도 차지하지 않게 했다(`border-r`이면 209·176px이 된다). Figma는 선이 프레임 안쪽에 그려져 여백에 영향을 주지 않는다.
- 펼친 LNB의 드롭다운 아이콘(Chevron)은 하위 화면 연결 여부와 관계없이 16px 아이콘 + 2px 여백 = **20×20 영역**, 행 오른쪽 여백 **12px**로 모든 행에서 같은 자리에 정렬한다(디자인팀 QA 2026-10-28, Figma Icon Button `5052:72817`).
- 캠페인·인플루언서·커머스 판매현황 및 캠페인 등록은 준비 중이며 비활성화한다. 마이페이지(구독·빅버드 머니·계정 설정)는 연결돼 있다. 고객센터 메뉴는 비로그인 클릭 시 `/login`으로 이동하며, 접근 권한이 있는 로그인 사용자에게 빅버드 문의·구매자 문의 진입 링크를 제공한다. 빅버드 문의 목록·구매자 문의는 준비 중 안내, `/customer-center/bigbird/new`는 새 문의 폼 UI이며 API 연동은 후속 작업이다.
- 캠페인 등록 버튼은 기능 연결 전까지 클릭을 막되, 사용자 요청에 따라 시안의 기본 색상·불투명도를 유지한다.
- 헤더 포인트는 빅버드 머니 잔액을 보이고(읽기 전·실패 시 `—`) 누르면 `/mypage/money`, 프로필 메뉴의 계정 설정은 `/mypage/account`로 간다.
- 알림 벨은 누르면 Figma `Alert List`(빈 상태 `7318:176591`, 목록 `8711:139090`) 팝오버를 연다. API 연동 전에는 항상 "새로운 알림 없음"이다. 읽음 처리·FCM은 [home.md](home.md) §4·§5.
- 홈 본문(히어로·검색·카드)은 로그인·비로그인 모두 같고 [home.md](home.md)에 있다. 예전 세션·권한 요약 본문은 없앴다. 로그인 후 대시보드 본문은 후속 작업이다.
- `AppShell`은 `mainClassName`으로 본문 여백(기본 `p-5`)을 바꿀 수 있다. 홈은 배경이 영역을 꽉 채우도록 `p-0`을 쓴다.

## LNB 메뉴 구성과 권한 (후속 적용)

2026-10-20 사용자 답변 기준입니다. 해당 메뉴·화면이 생길 때 적용합니다(홈 스펙에서 옮겨 옴). 인플루언서 매칭(하위: 검색)·인플루언서 마켓 분리는 앱 셸에 적용했고, 나머지는 후속입니다.

- **메뉴 구성:** 홈, 캠페인 ▾(캠페인 현황·등록 중 캠페인·진행 중 캠페인), **인플루언서 매칭 ▾**(인플루언서 검색·인플루언서 관리·채팅. 관리·채팅은 화면이 없어 목적지 없이 비활성이고 **비로그인이 누르면 로그인 안내 알럿**, 로그인하면 "준비 중". 디자인팀 QA 2026-10-28. 영문 LNB 이름은 "Matching"), **인플루언서 마켓 ▾**(하위 메뉴 미정), 커머스 관리 ▾(판매현황 관리·캠페인 정산, 화면이 없어 목적지 없이 비활성. 디자인팀 QA 2026-10-28), 마이페이지 ▾(구독·빅버드 머니·계정 설정), 고객센터 ▾(빅버드 문의·구매자 문의). 기존 "인플루언서 ▾(인플루언서 검색·인플루언서 관리·채팅)"는 인플루언서 매칭·인플루언서 마켓으로 바뀌고, "커머스 판매현황"은 "커머스 관리 ▾"로 바뀝니다(마이페이지 시안 3.0.4). 모든 기기에서 같습니다.
- **Sub ID 권한:** 계정 설정의 권한 항목은 **LNB 메뉴를 눌렀을 때 그 페이지 진입을 막는 권한**입니다. 권한이 없는 Sub ID에게도 메뉴는 보이고 **흐리게 비활성**으로 표시합니다(사용자 결정). URL로 직접 들어오면 세션 middleware의 서버 경로 권한 확인(`GET /v3/sec` + `X-Path`)을 따릅니다. 서버가 Sub ID에게 `/mypage/money`는 빅버드 머니 권한, `/customer-center/buyer`는 구매자 문의 권한이 있어야 통과시키고 `/mypage/subscribe`는 항상 거부합니다(403). 거부되면 로그인으로 보내지 않고, 앱 안의 이동이면 지금 화면에 머물고 첫 진입이면 홈으로 보낸 뒤 "해당 메뉴에 접근할 권한이 없습니다. Master ID에 권한을 요청해 주세요." 토스트를 띄웁니다. 돌아온 화면은 세션을 새로 받아 LNB 권한 표시를 갱신합니다. 구독은 토스트 없이 계정 설정으로 보냅니다.

|---|---|
| 캠페인 | 캠페인 |
| 인플루언서 매칭 | 인플루언서 매칭 |
| 인플루언서 마켓 | 인플루언서 마켓 |

- **적용 범위(2026-10-27):** LNB는 세션(`GET /v3/sec`)의 메뉴 권한 6개를 읽습니다(`GET /authorization/me`는 삭제됨). MASTER·ADMIN은 모두 활성이고 Sub ID는 마스터가 준 값을 호출할 때마다 새로 읽습니다. 지금 화면이 있는 메뉴에 적용했습니다: 인플루언서 매칭 > 검색(`isInfluencerMatchingAccess`), 마이페이지 > 빅버드 머니(`isBigbirdMoneyAccess`), 고객센터 > 구매자 문의(`isPurchaserQuestionAccess`). 빅버드 문의는 모두 활성이고, 캠페인·인플루언서 마켓·커머스 관리는 화면이 생길 때 같은 방식으로 적용합니다.
- Sub ID는 권한과 관계없이 **마이페이지 > 구독에 들어갈 수 없습니다**(흐리게 비활성). 마이페이지 > 계정 설정은 항상 들어갈 수 있고 Sub ID용 탭 구성은 [mypage/account.md](mypage/account.md).
- **비로그인 정책:**
  - 1차 메뉴는 로그인 여부와 관계없이 활성이고, 비로그인이 누르면 로그인 안내 얼럿을 띄웁니다. 얼럿은 Figma Alert Dialog `10132:97915` 기준입니다(`shared/components/login-required-alert`: 제목 "로그인 필요", 본문 "해당 메뉴는 로그인 시 접근이 가능한 메뉴입니다.", 버튼 "취소"/"로그인하러 가기" → `/login`). 지금은 LNB 인플루언서 관리·채팅과 홈 카드(인플루언서 추천·캠페인 등록/운영)에 적용했고, 나머지 1차 메뉴는 기존처럼 로그인으로 바로 이동합니다.
  - 2차 메뉴는 비로그인이 접근할 수 없는 것만 비활성입니다. 세부 접근 표는 아직 미정입니다(그룹 메뉴 클릭 시 얼럿 여부, 2차별 접근 가능 여부, 비활성 클릭 동작, "캠페인 등록하기" 처리, 비활성 2차 스타일, 로그인 후 원래 화면으로 돌아갈지).
- **레일에서 하위 메뉴가 있는 메뉴를 누르면(디자인팀 QA 2026-11-06):** 어느 화면으로도 이동하지 않고 LNB를 펼치면서 그 메뉴 그룹을 펼칩니다(예: 홈에서 마이페이지 아이콘 → LNB 펼침 + 마이페이지 그룹 열림). PC는 사이드바를 펼치고, 태블릿은 전체 메뉴(Sheet)를 엽니다. 하위 메뉴가 없는 홈·캠페인 아이콘은 그대로 이동합니다. 눌러서 연 그룹 외의 그룹은 현재 화면이 속한 그룹만 열려 있습니다.
- **768 이상 1440 미만:** 태블릿 규칙을 따릅니다.
- 태블릿 비로그인 프레임에 커머스 메뉴가 없는 것과 캠페인 ▾가 빠진 프레임들은 Figma 누락입니다.

## 로그아웃과 버튼 상태

- 프로필 드롭다운은 Figma `7334:157642` 기준: 48px 아바타, 사용자명·이메일, 20px 설정 버튼, 36px 로그아웃 행이다.
- 로그아웃은 `POST /v3/auth/logout`(2026-11-04 Stage)을 사용한다. 서버가 세션을 끝내고 쿠키를 지운 뒤 `200 { result: true }`를 주며(세션이 없어도 200) 리다이렉트하지 않는다. 호출 전에 이 기기의 채팅방 잠금을 풀고, 성공하면 현재 앱의 `/`를 새로 로드해 세션·캐시를 정리한다. V2 `GET /logout`은 설정된 주소로 302하므로 쓰지 않는다.
- 요청 중에는 중복 로그아웃을 막고, 실패 시 현재 화면에서 오류 안내 후 재시도할 수 있다.
- 프로필·메뉴 열기·이용 가이드·로그인·로그아웃은 호버 배경과 포인터를 제공한다. 프로필을 열면 시안의 Focus 상태(흰 배경, 위쪽 화살표)를 표시한다.
- 캠페인 등록 버튼의 색상은 시안을 유지한다.
