## 1. 목적과 범위

- 광고주 Master 계정이 자기 정보·회사 정보·정산 계좌·하위 계정(Sub ID)·알림 수신 동의를 관리합니다. v2 `/account`(섹션 세로 나열 + 모달)를 탭 화면으로 바꿨습니다.
- **Master ID와 Sub ID**: Master ID는 광고주(회사) 계정입니다. Master가 직원용 Sub ID를 개설하면 Sub ID가 로그인해 권한을 받은 작업을 합니다. Sub ID 목록에는 Master가 나오지 않습니다.
- **Master(MASTER·ADMIN)와 Sub ID(SUB) 화면을 모두** 만들었습니다. Sub는 Master ID 관리 탭이 **"Sub ID 관리"**(본인 정보)로 이름이 바뀌고 알림 설정 탭이 있으며, 간편 로그인 연동 카드·회원 탈퇴 버튼·회사정보·계좌정보·Sub ID 관리 탭이 없습니다.
- **Sub ID는 마이페이지 > 구독에 들어갈 수 없습니다**(2026-10-22). 빅버드 머니를 Master와 Sub가 공유하는 구조라 구독 상품도 Master가 결제·관리하고 Sub는 이용 권한만 공유받습니다. `/mypage/subscribe`를 주소로 열면 `MypageLayout`이 `/mypage/account`로 `replace` 이동시킵니다. LNB 구독 메뉴의 Sub 비활성은 구독 화면을 구현할 때 함께 적용합니다.
- **로그인 착지점**은 권한과 관계없이 홈(`/`)입니다(2026-10-22 사용자 결정, [../auth/login.md](../auth/login.md)).

### API와 목 데이터 (마이페이지 3종 공통 규칙)

- 공개된 V3 API([docs/mypage-api.md](../../docs/mypage-api.md))의 응답이 화면을 그리기에 충분하면 **API를 연결**합니다(Zod → 트랜스포머 → SWR). 부족하거나 없는 화면만 목 데이터를 씁니다.
- **목 데이터는 화면 구현 확인용으로만** 씁니다. API가 공개되면 목 분기(목 파일, 목을 돌려주는 훅 내부, 임시 코드값)를 **흔적 없이 지웁니다.** 실제 사용자에게 목 데이터가 보이는 상태로 배포하지 않습니다.
- 목을 쓰는 동안 서버에 반영되는 동작(저장·생성·삭제·연동·업로드·동의 변경)은 **성공한 것처럼 보이지 않게** 합니다. 확인 다이얼로그까지는 시안대로 진행하고 마지막 서버 단계에서 "준비 중인 기능입니다." 토스트를 띄운 뒤 값은 바꾸지 않습니다. API를 연결한 동작은 실제로 호출합니다.
- 응답 형태는 추측해 Zod 스키마로 만들지 않습니다. Zod 스키마는 Swagger 필드로만 만들고, 목은 화면용 뷰모델 타입만 둡니다.
- **목은 개발 서버에서만(2026-10-22 사용자 결정)**: API가 없거나 화면을 그리기에 부족한 곳은 **개발 서버(`pnpm dev`)에서만 목으로 그리고, 빌드(stage·prod)에서는 그 자리에 공통 `EmptyState`(`construction`, "준비 중인 기능입니다.")를 둡니다.** 분기는 `import.meta.env.DEV`이고, 목 값도 개발 서버에서만 채워 빌드 번들에 들어가지 않습니다. API가 공개되면 목 분기·`DEV` 분기를 실제 훅으로 바꾸고 목 파일을 지웁니다.
  - 남은 목(2026-10-23): **Sub ID 캠페인 할당**만. `features/manage-sub-accounts/model/mock-permission.ts`, `api/use-sub-account-permissions.ts`의 `useCampaignAssignments`(임시 코드값 `lib/use-code-label.ts`, B-6). `GET /campaign`은 있으나 "진행 상태" 열의 기준이 정해지지 않았습니다(B-3). 빌드에서는 권한 부여 아래 "Sub ID 캠페인 할당" 섹션 본문이 준비 중입니다.
  - 서버 반영을 막아 둔 동작(준비 중 토스트): 캠페인 할당 스위치, 간편 로그인 연동·해제
  - 그 밖(Master·Sub 본인 정보, 회사정보, 계좌정보, Sub ID 목록·검색·생성·삭제·권한, 비밀번호·이메일·휴대폰 인증·프로필 이미지, 회원 탈퇴, 알림 설정)은 실제 API입니다.

### 수정 구조(2026-10-27 시안·사용자 결정)

Master ID 관리(기본 정보)·회사정보·계좌정보는 **보기 화면 → "수정"(계좌 미등록은 "등록") → 관리자 비밀번호 입력 → 같은 카드가 입력 모드 → 취소·저장** 구조입니다. 시안 원문은 `.claude/figma-cache/mypage-setting-edit-flow.md`(로컬)에 있습니다.

- 비밀번호 확인은 **화면마다 따로** 합니다(한 번 통과해도 다른 화면 수정에 이어지지 않음). 입력 모드를 취소하거나 저장하면 보기로 돌아가고, 다음 "수정"에서 다시 묻습니다.
- 비밀번호 확인은 `POST /check/pw`(회원 탈퇴와 같음)를 씁니다. 오류 문구는 시안에 없어 임시 문구를 적용합니다(P-6에 모음).
- 기본 정보는 "정보 수정" 카드를 없애고 한 카드로 합칩니다. 간편 로그인 연동 카드는 그대로입니다.
- 계좌정보 은행은 시안이 입력칸이나 **Select를 유지**합니다. 회사정보가 없으면 계좌정보 탭 진입 때 얼럿을 띄우는 기존 결정도 **유지**합니다(시안의 "계좌정보 알럿 호출 삭제" 주석과 다름, 사용자 결정).
- **회사정보(2026-10-27 구현)**: 보기에서 서류는 파일명 다운로드 버튼이고, 사업자 등록증 `GET /company/registration/download`·통신판매업 신고증 `GET /company/mailorder/download`로 내려받습니다(2026-10-28 연동, 통장 사본과 같은 처리). **등록된 회사정보가 없으면 보기 없이 곧바로 입력 모드**로 열립니다(비밀번호 확인 없음, 시안에 없는 경우라 v3 임의 결정). 취소·저장 성공 뒤 보기로 돌아가고, 일부만 저장에 실패하면 입력 모드에 머뭅니다. 시안에 제목이 없어 "회사정보" 제목은 화면 낭독용으로만 둡니다.
- **계좌정보(2026-10-27 구현)**: 보기(은행·계좌번호·예금주·통장 사본)와 아래 "수정", 미등록이면 값 `-`·통장 사본 "등록된 파일이 없습니다" 뱃지·"등록" 버튼입니다. "수정"·"등록" 모두 비밀번호 확인 뒤 입력 모드이고(미등록 "등록"도 확인함, 시안에 없어 v3 임의 결정), 취소·저장 성공 뒤 보기로 돌아갑니다. 통장 사본은 `GET /bank/download`로 **내려받습니다**(2026-10-27 연동). 응답 헤더를 실제로 확인하지 못해 `shared/api`의 `download`가 blob으로 받고 파일 이름은 `Content-Disposition` → 계좌 조회의 원본 이름 → `bankbook` 순으로 씁니다. 실패(404 등)는 임시 오류 토스트 "파일을 내려받지 못했습니다. 다시 시도해 주세요."(P-6). 회사정보가 비었을 때 탭 진입 얼럿은 시안의 "알럿 호출 삭제"와 달리 유지합니다(사용자 결정).

  - **회원 탈퇴**: 시안 PC·TAB 수정 모드에 버튼과 약관 팝업이 있으나 `PUT /exit`가 Master 전용이라 Sub는 버튼을 그리지 않습니다(P-7②, §4-20).

| 간편 로그인 연동 | Master만. 카카오·네이버·구글·애플 4개 스위치. **페이스북은 연동하지 않아 시안에 있어도 그리지 않습니다**(사용자 결정 2026-10-29, 2026-10-21 "v3 필수" 결정을 대체). 등록·해제 API는 B-10. 켜면 해당 SNS 인증으로 이동하고 돌아오면 결과 토스트, 끄면 확인 알럿(시안에 없어 삭제 알럿과 같은 구조로 새로 둠) 후 해제합니다. 즉시 반영이고 저장 버튼과 무관합니다. 지금은 켜기·확인 모두 "준비 중" 토스트이고 스위치는 원래 값으로 둡니다 |

| 삭제 | 삭제 버튼 → Destructive 알럿. 제목 "Sub ID 삭제", 본문 "‘{아이디}’를 삭제하시겠습니까? 삭제된 데이터는 복구되지 않습니다.", 버튼 "취소"·"삭제". 모든 기기 통일, MO는 버튼 세로 배치(삭제 위·취소 아래). "삭제"는 `DELETE /sub/{accountIdx}` 후 목록을 다시 읽고 토스트 "Sub ID가 삭제되었습니다.", 실패는 오류 토스트. 지운 Sub ID의 권한 부여를 열어 두었으면 닫습니다 |

## 4. 배치

- 파일 첨부 행은 회사정보·계좌정보가 공유하는 `shared/components`의 파일 업로드 입력을 씁니다.
- 데이터를 읽는 훅은 공개 API가 있으면 SWR로 만들고, 목이 필요한 화면만 각 feature의 `model/mock.ts` 목을 돌려줍니다(§1). 세부 구조는 코드를 봅니다.

## 5. 데이터 흐름의 예외

- 공개 API를 연결한 화면은 표준 흐름(Zod → 트랜스포머 → SWR)을 따르고, 목 화면만 SWR·Zod 없이 뷰모델 타입만 둡니다. 어느 쪽이든 UI는 서버 필드명을 쓰지 않습니다.
- 응답 형태가 두 가지(HTTP 상태 + `V3ErrorResponse` / 항상 200 + `result`·`reason`)이고 계좌 등록은 `{result:true, reason:"denied"}`로 거부합니다([docs/mypage-api.md](../../docs/mypage-api.md) §2).
- 폼 상태는 각 feature가 소유하고 탭·하위 화면 상태는 URL 쿼리가 소유합니다.

## 6. 다국어

- 문구 원문은 각 namespace의 `locales/ko.json`이 원본입니다. 탭·카드 제목·라벨은 시안 문구입니다. Figma에 없는 문구(간편 로그인 해제 알럿·저장·생성·삭제 토스트·중복 확인·파일 형식·권한 변경·회원 탈퇴 비밀번호 단계 등)는 사용자 결정으로 추천 문구를 적용했고 임시 문구의 확인은 §7 P-6·P-2에 있습니다.
- 날짜는 `formatDate`. SNS 이름은 서비스 고유 용어가 아니라 브랜드명이라 언어별 통용 표기를 씁니다.
- **서버 값 다국어**는 `.claude/rules/i18n.md` "서버 데이터"를 따릅니다: 상태·유형·권한처럼 종류가 정해진 값은 서버가 **코드(enum)** 로 주고 프론트가 코드마다 번역 키를 둡니다. 목록에 없는 코드가 오면 서버 값을 그대로 표시합니다. 은행명·회사 분류·캠페인명처럼 DB에 쌓이는 값은 그대로 표시하고 다국어는 나중에 정합니다.

## 9. 검증

- `pnpm verify`, 해당하면 `pnpm build`
- 화면 확인(PC 1440·TAB 768·MO 360, 시안 대조, `?lng=en` 등으로 긴 문구 확인)
  1. 탭 전환·잘못된 `?tab=` 대체, 헤더 제목·LNB 활성. SUB는 탭 2개만, SUB가 `/mypage/subscribe`를 열면 계정 설정으로 이동
  2. 정보 수정: 비밀번호 규칙·불일치, 취소로 되돌리기, 저장 토스트. 회원 탈퇴는 실제 계정이 탈퇴되므로 목 응답으로만 확인(Master만 버튼, SUB는 없음)
  3. 간편 로그인 끄기 → 확인 알럿 → "준비 중", 스위치 값 유지
  4. 회사정보 필수 미입력 시 저장 비활성, 파일 형식·용량 오류, 서류 파일명 표시. 회사정보가 비면 계좌정보 탭에서 얼럿(확인 → 회사정보, 취소 → 기본 탭), 계좌정보 은행 Select

  6. TAB·MO 하위 화면: 뒤로가기로 닫힘, 새로고침 유지
  7. 알림 설정 토글 → 날짜 포함 동의·철회 토스트, 새로고침해도 값 유지. 실패하면 원래 값으로 되돌아감
