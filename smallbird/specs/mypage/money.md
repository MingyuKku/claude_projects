## 1. 목적과 범위

- 광고주가 플랫폼 안에서 쓰는 빅버드 머니를 **무통장 입금(가상계좌)으로 충전**하고, 충전 내역과 사용 내역(인플루언서 계약 비용, 부가 서비스)을 봅니다. v2 `/mileage`(비즈머니, PG 카드 결제)를 대체합니다.
- API와 목 데이터는 [account.md](account.md) §1 규칙을 따릅니다(공개 API가 충분하면 연결, 아니면 목. 목은 화면 구현 확인용이고 구현이 끝나면 흔적 없이 지움). 잔액(`GET /v3/mypage/bigbird-money`)·충전 내역(`POST …/charge`)·사용 내역(`POST …/usage`)·충전 요청용 초기 데이터(`GET …/init`)가 2026-10-23에 공개돼 **모두 실제 API로 연결**합니다. 거래 상세는 별도 API 없이 충전/출금 내역 항목의 필드로 그립니다(상세 API는 만들지 않기로 함, 2026-10-30). 목이 남는 곳은 없습니다(이니시스 결제창 연동은 §3 충전).
- 환불은 추가될 예정이나(기획 확정 2026-10-27) 시안이 아직 없어 범위 밖입니다. 충전 취소는 시안과 정책이 없어 범위 밖입니다(PRD 미정).
- Master(MASTER·ADMIN)와 **빅버드 머니 권한이 있는 Sub ID**가 들어올 수 있습니다(사용자 답변). 권한이 없는 Sub ID에게 LNB 마이페이지 > 빅버드 머니는 흐리게 비활성입니다([main.md](../main.md) "LNB 메뉴 구성과 권한"). 화면 구성은 Master와 같습니다.

### 시나리오

1. 헤더의 "P {보유 금액}" 또는 LNB 마이페이지 > 빅버드 머니로 들어오면 충전 내역 탭이 열립니다. 보유 빅버드 머니와 충전 안내를 봅니다.
2. "충전하기"로 충전 패널을 열고 금액을 입력(또는 빠른 금액)한 뒤 "{금액}원 충전하기"를 누르면 충전 요청이 접수되고, 충전 상세 내역에 "대기 중" 건이 생깁니다. 가상계좌 정보는 그 건의 거래 상세에서 봅니다.
3. 입금이 확인되면 그 건이 "입금 완료"가 되고 보유 금액이 늘어납니다. 입금 기한 날짜가 지나도록 입금하지 않으면 그 건은 "미입금 취소"(서버 `DEPOSIT_EXPIRED`, 기한 당일까지는 "대기 중")로 내역에 계속 보입니다(기획 확정 2026-10-27, 2026-10-30 API 반영).
   입금·출금 처리 시점을 화면이 알 수 없어 충전/출금 내역은 **탭 복귀·창 포커스 때 항상**, **"대기 중" 건이 보이는 동안은 3분마다**(숨은 탭 제외) 내역과 잔액을 함께 다시 읽습니다(`useChargeAutoRefresh`).
4. 사용 내역 탭에서 캠페인별 차감 내역과 사용 후 잔액을 봅니다.

## 5. 데이터 흐름의 예외

- 잔액·충전 내역·사용 내역 모두 공개 API를 표준 흐름(Zod → 트랜스포머 → SWR)으로 연결합니다([docs/mypage-api.md](../../docs/mypage-api.md) §2). 사용 내역은 캠페인 값이 없으면 `"-"`, 금액은 부호 포함이고, 목록 기본 `entrySize`가 사용 내역 8·충전 내역 5라 `entrySize`(10·20·50)를 항상 명시합니다. 사용 내역 필터의 캠페인 선택지는 `GET …/usage/filter-options`입니다.
- 거래 상세·사용 상세는 별도 API가 없어 목록 항목에서 만듭니다. 충전/출금 내역은 서버 `id`가 생겨(2026-10-30) 주소의 `?id=`가 `{구분}-{id}`이고 지금 보이는 목록(PC·TAB은 주소의 쪽·필터, MO는 이어 읽은 목록)에서 찾습니다. 사용 내역은 서버 `id`(사용 내역 코드)가 충전·출금까지 고유해 `?id=`가 그 값 그대로이고 같은 방식으로 찾습니다.
- 충전 요청은 V3가 프록시하지 않는 결제 서버(`bigbird-pay-be`)를 프론트가 직접 부르는 예외입니다. 응답 검증은 Zod로 하고 결제창 호출은 `features/charge-bigbird-money` 안에 둡니다.
- 충전/출금 내역의 구분·입금 상태는 서버 코드를 화면 코드로 바꿔 번역 키(충전·출금 / 입금 완료·출금 완료·대기 중·미입금 취소)에 씁니다. 사용 내역의 구분 `type`(`USE`·`REFUND`·`CHARGE`·`WITHDRAWAL`)·캠페인 유형 `campaignType`(`recruit`·`pick`)·사용 내역 `usageDetailCode`(4가지)도 코드를 화면 코드로 바꿔 번역 키에 씁니다. 모르는 값은 서버 값(`usageDetailName` 포함)을 그대로 보이고 구분은 회색 배지.
- 헤더 보유 금액은 이 페이지와 같은 훅(같은 SWR 키)을 써서 충전 복귀 뒤 두 곳이 같이 갱신됩니다.
