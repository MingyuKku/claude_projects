## 1. 목적과 범위

- 광고주가 플랫폼 안에서 쓰는 빅버드 머니를 **무통장 입금(가상계좌)으로 충전**하고, 전액 출금을 요청하고, 충전/출금 내역과 사용 내역(인플루언서 계약 비용, 부가 서비스)을 봅니다. v2 `/mileage`(비즈머니, PG 카드 결제)를 대체합니다.
- 잔액·충전/출금 내역·사용 내역·충전 초기 데이터·출금 모두 실제 API입니다. 거래 상세·사용 상세는 별도 API 없이 목록 항목의 필드로 그립니다(상세 API는 만들지 않기로 함, 2026-10-30). 목은 없습니다.
- 환불은 추가될 예정이나(기획 확정 2026-10-27) 시안이 없어 범위 밖입니다. 충전 취소도 시안·정책이 없어 범위 밖입니다.
- Master(MASTER·ADMIN)와 **빅버드 머니 권한이 있는 Sub ID**가 들어올 수 있습니다. 권한이 없는 Sub ID에게 LNB 마이페이지 > 빅버드 머니는 흐리게 비활성입니다(세션 `isBigbirdMoneyAccess`, [main.md](../main.md) "LNB 메뉴 구성과 권한"). 화면 구성은 Master와 같습니다.

### 시나리오

1. 헤더의 "P {보유 금액}" 또는 LNB 마이페이지 > 빅버드 머니로 들어오면 충전/출금 내역 탭이 열립니다. 보유 빅버드 머니와 충전 안내를 봅니다.
2. "충전하기"로 충전 패널을 열고 금액을 입력(또는 빠른 금액)한 뒤 "{금액}원 충전하기" → 약관 동의 → 이니시스 결제창 → 복귀하면 충전 요청이 접수되고 "대기 중" 건이 생깁니다. 가상계좌 정보는 그 건의 거래 상세에서 봅니다.
3. 입금이 확인되면 그 건이 "입금 완료"가 되고 보유 금액이 늘어납니다. 입금 기한 날짜가 지나도록 입금하지 않으면 "미입금 취소"(서버 `DEPOSIT_EXPIRED`, 기한 당일까지는 "대기 중")로 내역에 계속 보입니다.
   입금·출금 처리 시점을 화면이 알 수 없어 충전/출금 내역은 **탭 복귀·창 포커스 때 항상**, **"대기 중" 건이 보이는 동안은 3분마다**(숨은 탭 제외) 내역과 잔액을 함께 다시 읽습니다.
4. "출금하기"로 전액 출금을 요청합니다(계좌 직접 입력 + 통장 사본). 잔액은 운영자가 처리할 때 빠집니다.
5. 사용 내역 탭에서 캠페인별 차감·환급과 충전·출금, 사용 후 잔액을 봅니다.

- 목록 기본 `entrySize`가 사용 내역 8·충전 내역 5라 `entrySize`(10·20·50)를 항상 명시합니다.
- 거래 상세·사용 상세는 별도 API가 없어 목록 항목에서 만듭니다. 충전/출금 내역 주소의 `?id=`는 `{구분}-{id}`, 사용 내역은 서버 `id` 그대로입니다.
- 충전 요청은 V3가 프록시하지 않는 결제 서버(`bigbird-pay-be`)를 프론트가 직접 부르는 예외입니다(쿠키 없이 요청). 응답은 Zod로 검증합니다.
- 구분·입금 상태·캠페인 유형·사용 내역 코드는 서버 코드를 화면 코드로 바꿔 번역 키에 쓰고, 모르는 값은 서버 값(`usageDetailName` 포함)을 그대로 보이며 구분은 회색 배지입니다.
