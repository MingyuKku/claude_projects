## 1. 목적과 범위

- 광고주가 빅버드 머니를 **무통장 입금(가상계좌)으로 충전**하고, 전액 출금을 요청하고, 충전/출금 내역과 사용 내역(인플루언서 계약 비용, 부가 서비스)을 봅니다. v2 `/mileage`(비즈머니, PG 카드 결제)를 대체합니다.
- 모두 실제 API이고 목은 없습니다. 거래 상세·사용 상세는 **상세 API 없이 목록 항목으로** 그립니다(상세 API는 만들지 않기로 함).
- Master와 **빅버드 머니 권한이 있는 Sub ID**가 들어옵니다(세션 `isBigbirdMoneyAccess`, 없으면 LNB 메뉴가 흐림, [main.md](../main.md)). 화면은 Master와 같고 Sub도 출금할 수 있습니다.
- 입금 확인은 운영·이니시스 쪽에서 일어나 화면이 시점을 알 수 없으므로, 충전/출금 내역은 **탭 복귀·창 포커스 때마다**(5초 안에 겹치면 한 번), **"대기 중" 건이 보이는 동안 3분마다**(숨은 탭 제외) 내역과 잔액을 함께 다시 읽습니다.
- 환불(추가 예정, 시안 없음)과 충전 취소는 범위 밖입니다.

| 휴대폰 충전(함정) | `INIStdPay.pay()`는 휴대폰이면 "PC로 결제 진행" 알림만 띄우고 끝나서(iOS·Android) 휴대폰은 모바일 일반결제로 나눔. **기기 판별은 이니시스 `INIStdPay_third-party.js`의 `mobileBrowser` 정규식과 같아야 함**(다르면 PC 흐름으로 갔다가 막힘, iPadOS Safari·Android 태블릿은 PC). `MOBILE`이면 `closeUrl` 없이 보내고 응답 `{ paymentUrl, form }`을 숨은 폼으로 `paymentUrl`에 같은 창 POST하며 한글이 깨지지 않게 **EUC-KR**(`accept-charset`) |
| 결제 복귀 판정 | 결제 서버가 `redirectUri` 뒤에 `?isPaid=true&gopaymethod=…&goodName=…`를 붙여 돌려보냄(옛 `/client/pay`의 `isPaied`가 아님). 복귀하면 결과와 상관없이 잔액·내역을 다시 읽고, 접수 알럿은 `isPaid=true`일 때만. `isPaid=false&code=PAYMENT_FAILED\|USER_CANCELED`는 문구가 정해지지 않아 알럿 없음(P-3, **지금은 취소도 `PAYMENT_FAILED`로 옴**, A-7). `redirectUri`를 쿼리 없이 보내므로 **복귀 주소의 쿼리는 이름과 상관없이 모두 지움**(가상계좌 번호·입금기한이 주소에 남던 문제) |
| 충전 요청 후 | 알럿 "충전 요청 완료"(확인만) → 패널을 닫고 충전/출금 내역으로, 새 건은 "대기 중". 가상계좌는 그 건의 거래 상세에서 봄 |

### 출금

`POST …/bigbird-money/withdraw`(multipart, [docs/mypage-api.md](../../docs/mypage-api.md) §2). **전액 출금 + 출금 계좌 직접 입력**(3.0.9, 금액 입력 없음). **잔액은 운영자가 처리할 때 빠지므로** 요청 직후 잔액은 그대로이고, 처리 중인 출금이 있으면 새 요청 불가(409).

## 4. 배치

- 환경변수: `VITE_API_PAY_URL`(결제 서버 경로 접두사), `VITE_PROXY_PAY_URL`(개발 프록시 대상), `VITE_INICIS_STDPAY_URL`(이니시스 표준결제 스크립트, 결제창 닫기 스크립트 호스트도 여기서 정하고 이니시스 호스트만 허용).

## 5. 데이터 흐름의 예외

- 목록 기본 `entrySize`가 사용 내역 8·충전 내역 5라 `entrySize`(10·20·30)를 항상 명시합니다.
- 충전/출금 내역은 충전·출금 번호가 겹칠 수 있어 주소의 `?id=`가 `{구분}-{id}`이고, 사용 내역은 서버 `id` 그대로입니다.
- 충전 요청은 V3가 프록시하지 않는 결제 서버(`bigbird-pay-be`)를 프론트가 직접 부르는 예외입니다(쿠키 없이 요청, 응답은 Zod 검증).
