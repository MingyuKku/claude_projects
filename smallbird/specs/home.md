| 키보드 활성 배치 | 태블릿·모바일에서 가상 키보드가 떠 있는 동안 **카드가 입력창 위로 올라가고**(입력창이 4~8줄로 늘면 자리를 차지하지 않고 위로 커지며 카드를 덮음) 히어로는 그대로 둡니다. **입력창은 본문 아래 끝(아래 여백 16px 위)에 `position: sticky`로 고정되고 그 뒤로 본문만 스크롤됩니다**(디자인 QA 2026-11-02, 입력창 밖을 끌면 입력창이 키보드 아래나 화면 위로 사라지던 문제). sticky는 부모 영역 안에서만 붙으므로 히어로·입력창·카드는 묶음 없이 본문 컨테이너의 직속 자식이고, 간격은 gap 대신 요소별 위 여백으로 줍니다. 기준이 문서가 아니라 본문 스크롤 영역(`<main>`)이고 그 아래 끝이 키보드 위 경계라, 문서 기준 sticky가 iOS 키보드 뒤로 가는 문제([WebKit 202120](https://bugs.webkit.org/show_bug.cgi?id=202120))를 피합니다(스크롤 영역 안 sticky 어긋남 [WebKit 231953](https://bugs.webkit.org/show_bug.cgi?id=231953)은 Safari 15.5에서 수정). 입력창 높이는 접힌 상태(최소 4줄·최대 8줄)도 보이는 영역을 넘지 않게 줄이고 넘치면 입력창 안에서 스크롤하며, **최소 1줄**은 남깁니다(2026-11-02 사용자 결정). 1줄도 들어가지 않을 만큼 보이는 영역이 낮으면(가로 모드 등) 그때만 입력창이 보이는 영역을 넘고 고정이 풀려 본문과 함께 스크롤됩니다. 공간이 부족해도 위아래 여백은 줄이지 않습니다(2026-11-02 사용자 결정). 키보드가 없는 모바일은 입력창이 늘면 카드를 아래로 밀어냅니다(`MO / Main Screen` `10132:97768`)(`6886:38324`에 히어로가 없는 것은 표현상 생략). 순서는 CSS `order`만 씁니다(Tab 순서와 시각 순서 불일치는 수용). 감지는 텍스트 입력 포커스 + 터치 기기 + 1440 미만 + `visualViewport`가 키보드 전보다 150px 이상 축소이며, 하드웨어 키보드 태블릿과 1440 이상은 제외합니다. iOS는 키보드가 레이아웃을 줄이지 않으므로 셸을 `visualViewport` 높이로 줄이고 iOS가 내린 만큼 따라 내려 Android와 같은 모습으로 맞춥니다(챗지피티 웹 방식, 2026-10-28 사용자 결정. 이전의 방안 A "헤더 밀려남 수용"을 대체). 키보드가 열리는 순간과 셸이 줄어든 직후 한 번씩 본문 끝(입력창+버튼 줄)을 보이게 스크롤합니다(iOS는 커서까지만 스크롤해 버튼 줄이 가려짐, 앵커는 본문 컨테이너). 방식·안전장치·근거는 `.claude/skills/mobile-keyboard/SKILL.md` "iOS 셸 맞춤"에 있습니다. 키보드가 떠 있는 동안 셸 바깥(키보드 뒤 영역)을 터치로 끌지 못하게 막고, 셸 아래와 셸 배경을 홈 배경 아래 끝 색(태블릿 가로 그라데이션 그대로, 모바일은 대각선 그라데이션 아래 끝 색 blue-100 → 60% blue-50 → blue-200 근사)으로 칠하고, 본문을 스크롤해 내용이 보이는 영역 아래 끝을 지날 때 잘린 듯 보이지 않게 본문 아래를 입력 영역 여백(`--keyboard-anchor-gap`, 1rem)만큼 흐리게 합니다(사용자 결정 2026-10-28, 키보드가 열려도 제목은 유지). iOS 실기기에서 본문 축소·입력창 가림 해소는 확인했습니다(2026-10-28). **iOS 실기기 확인 대기**: 셸 바깥 끌기가 막히는지, 드러나더라도 흰 여백 대신 배경이 보이는지. 키보드 위 입력 보조 막대(↑ ↓ ✓)가 버튼 줄을 가리던 문제(실측 약 82pt)가 남는지도 함께 확인합니다 |
| 다국어 | 입력창 접근성 이름은 Figma에 라벨이 없어 안내 문구를 씁니다. "펼치기"·"축소"는 시안에 아이콘만 있어 spec 표현으로 만들었습니다. 번역 판단: `인플루언서 탐색` → en `Find influencers`·ja `インフルエンサーを探す`·zh-CN `查找网红`(소개 페이지가 `网红`를 씀), 플랫폼 라벨 ja `媒体`·zh-CN `平台`, 네이버 ja `ネイバー`. 백엔드 번역 요청 항목은 없습니다 |

## 5. 후속 작업에 적용할 결정 (이번 범위 아님)

사용자에게 받은 답변입니다. 해당 메뉴·API·화면이 생길 때 적용합니다.

**메뉴·LNB 정책**: 공통 셸이라 [main.md](main.md) "LNB 메뉴 구성과 권한"으로 옮겼습니다(2026-10-20 사용자 지시).

**카드 연결 시**
- "캠페인 등록/운영" → 캠페인 현황, "요금 안내" → 마이페이지 > 구독입니다. 비로그인 알럿은 인플루언서 추천·캠페인 등록/운영에 적용했고(§3), 요금 안내의 비로그인 처리는 디자인팀 지시를 받으면 적용합니다.

**헤더 기능 연결 시 (API 연동 후)**
- **빅버드 머니:** 헤더 "P"는 빅버드 머니입니다. 호버해도 아이콘은 그대로이고(디자인 QA, 2026-11-02), 누르면 마이페이지 > 빅버드 머니 화면으로 갑니다. 세부는 [mypage/money.md](mypage/money.md) §3 "헤더 P 연결".
- **알림:** 항목을 누르면 읽음 처리만 하고 페이지는 이동하지 않습니다. 패널 바깥을 클릭하면 닫힙니다.
- **계정 설정:** 프로필 설정(톱니)은 마이페이지 > 계정 설정으로 갑니다.
- **알림 수신:** FCM 웹푸시를 씁니다.
  - **권한 요청 제안(승인 필요):** 비로그인에게는 요청하지 않습니다. 접속하자마자 권한 창을 띄우지 않고, 로그인 사용자가 처음 알림 패널을 열 때 앱 안 안내 배너를 보여 줍니다. 사용자가 [알림 켜기]를 누를 때만 `Notification.requestPermission()`을 호출합니다. [나중에]를 누르면 일정 기간(예: 14일) 배너를 다시 띄우지 않습니다.
  - **권한 거부·미지원 시:** 다시 묻지 않고 앱 안 알림(벨·패널)만 씁니다. iOS Safari 일반 탭처럼 웹푸시를 지원하지 않는 환경에서는 배너를 띄우지 않습니다.
  - **로그아웃 시:** FCM 토큰을 삭제하고 서버 등록도 해제합니다.
  - `firebase` SDK와 Service Worker 추가는 팀 승인 절차를 따릅니다.
