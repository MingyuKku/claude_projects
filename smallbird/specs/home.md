사용자에게 받은 답변입니다. 해당 메뉴·API·화면이 생길 때 적용합니다.

**메뉴·LNB 정책**: 공통 셸이라 [main.md](main.md) "LNB 메뉴 구성과 권한"으로 옮겼습니다(2026-10-20 사용자 지시).

**카드 연결 시**
- "캠페인 등록/운영" → 캠페인 현황, "요금 안내" → 마이페이지 > 구독입니다. 비로그인 알럿은 크리에이터 추천·캠페인 등록/운영에 적용했고(§3), 요금 안내는 비로그인도 구독 화면으로 연결했습니다(2026-11-16).

**헤더 기능 연결 시 (API 연동 후)**
- **빅버드 머니:** 헤더 "P"는 빅버드 머니입니다. 호버해도 아이콘은 그대로이고(디자인 QA, 2026-11-02), 누르면 마이페이지 > 빅버드 머니 화면으로 갑니다. 세부는 [mypage/money.md](mypage/money.md) §3 "헤더 P 연결".
- **알림:** 항목을 누르면 읽음 처리만 하고 페이지는 이동하지 않습니다. 패널 바깥을 클릭하면 닫힙니다. 누르는 즉시 읽음으로 보이고 요청이 실패하면 되돌리며, 끝나면 목록을 다시 읽어 개수를 맞춥니다. 벨의 점은 패널을 열기 전에도 보여야 해서 목록이 아니라 서버가 센 전체 `unreadCount`를 씁니다. 목록은 첫 쪽 20건만 읽고(더 보기 시안 없음), 로그인 직후·창이 다시 활성화될 때·푸시를 받았을 때만 읽으며 폴링하지 않습니다. 목록 500은 빈 상태와 점 숨김(토스트 없음). 문구는 `type`(`CAMPAIGN_APPROVED`·`CAMPAIGN_REJECTED`)별 번역 키이고 용어는 "승인"·"반려"입니다(시안의 "거절"은 쓰지 않음, 2026-11-19 사용자 확인). 모르는 `type`은 목록에서 뺍니다. Sub ID는 알림 API가 403이라 호출하지 않고 항상 "새로운 알림 없음"입니다.
- **계정 설정:** 프로필 설정(톱니)은 마이페이지 > 계정 설정으로 갑니다.
- **알림 수신:** 벨 목록은 서버에 저장된 알림 기록(REST)이 기준이고, FCM 웹푸시는 새 알림을 알리는 신호입니다. Firestore 실시간 구독은 쓰지 않습니다(2026-11-19). 푸시를 못 받아도(브라우저 닫힘·권한 거부·미지원) 목록에는 쌓입니다.
  - **알림 설정과 별개:** 마이페이지 알림 설정(광고성·야간 수신 동의)은 법적 수신 동의로, FCM 기기 등록·브라우저 알림 권한과 다릅니다. 그래서 그 탭에 기기 토글을 두지 않습니다. 승인·반려는 필수 알림이라 동의와 관계없이 보냅니다(백엔드 기준, 기획 최종 확인 중).
  - **권한 요청(2026-11-19 사용자 결정):** 비로그인에게는 요청하지 않고, 접속하자마자 권한 창을 띄우지 않습니다. **주 입구는 승인 요청 순간**입니다. 캠페인 등록 8단계의 "결제 완료" 알럿과 반려 뒤 "재승인 요청 완료" 알럿에서 "확인"을 누를 때 등록 내역으로 가기 전에 브라우저 알림 권한 창을 바로 띄웁니다(우리가 그리는 안내 배너 없이, 알럿 UI·문구는 그대로). 권한이 아직 정해지지 않은 브라우저(`default`)에서만 묻고, 허용하면 이 기기를 바로 등록합니다. Sub ID는 알림을 받지 않아 묻지 않습니다. 클릭 핸들러 안에서 동기로 호출해야 합니다(Safari는 직접 사용자 동작에 대한 응답으로만 권한 요청을 허용, WebKit 공식 문서). 이 알럿은 새로고침해도 이어지는 흐름이 아니라 한 번의 클릭이므로 "나중에" 기간 같은 상태를 두지 않습니다. **벨 패널은 나중에 보조 입구로 추가합니다**(차단된 경우의 "브라우저 설정에서 허용" 안내, 결제 이력이 있는 기존 사용자). 그 배너 시안은 확인 중이고, 이전에 정한 "알림 패널을 처음 열 때 배너" 방식은 이 보조 입구로 대체합니다. 결제 알럿에 알림 안내 문구를 더할지는 시안·기획 확인 뒤 결정합니다.
  - **권한 거부·미지원 시:** 다시 묻지 않고 앱 안 알림(벨·패널)만 씁니다. 차단된 경우 코드로 다시 물을 수 없어, 벨 패널 보조 입구가 생기면 거기서 "브라우저 설정에서 허용" 안내를 보입니다(아직 없음). iOS Safari 일반 탭처럼 웹푸시를 지원하지 않는 환경에서는 묻지 않습니다.
  - **등록:** 권한이 이미 허용된 브라우저는 로그인·새로고침·계정 전환 뒤에 팝업 없이 토큰을 받아 등록(`POST /v3/notifications/devices`, `platform: "WEB"`)합니다. 같은 토큰을 반복해 등록해도 되고, 같은 브라우저에서 다른 계정으로 로그인하면 서버가 토큰을 새 계정으로 옮깁니다.
  - **로그아웃 시:** 서버에서 이 기기만 끕니다(`DELETE /v3/notifications/devices?token=`). 세션이 필요해 로그아웃 요청 **전에** 부르고, 끄기가 실패해도 로그아웃은 진행합니다. 로그아웃 요청 자체가 실패해 로그인 상태로 남으면 꺼 둔 기기를 다시 켜 보지만, 세션 만료나 네트워크 장애가 원인이면 이 재등록도 실패해 새로고침 전까지 푸시가 꺼진 채 남을 수 있습니다(끄기와 로그아웃이 한 번에 처리되지 않는 구조의 한계). 브라우저의 FCM 토큰은 지우지 않으며 다음 로그인 때 같은 토큰을 다시 등록합니다. 등록한 토큰은 로그아웃 때 FCM과 통신하지 않도록 `localStorage`(`bigbird.pushToken`)에 둡니다.
  - **기기 상태 조회(`GET …/status`):** 기기별 토글 화면이 없어 쓰지 않습니다.
  - **푸시 표시(2026-11-19):** 서버는 제목·문구 없는 data 메시지(`type`·`notificationIdx`·`campaignIdx`·`campaignName`)만 보내서 `public/web-push-message.js`가 `type`으로 문구를 만듭니다(`public/firebase-messaging-sw.js`가 불러옴). 앱 알림 목록의 문구(`widgets/app-shell` 번역)와 같게 유지해야 하고, 어긋나도 자동으로 잡히지 않습니다. 서비스워커는 앱에서 고른 언어를 읽을 수 없어 **브라우저 언어**(ko·en·ja·zh-CN, 그 밖은 ko)를 따르므로 앱 안 목록과 언어가 다를 수 있습니다(기획 확인 중).
  - **푸시마다 항상 알림을 띄웁니다(앱 창이 화면에 보여도, 모르는 `type`이어도).** Safari(iOS 홈 화면 웹앱 포함)는 알림 없는 푸시를 허용하지 않고, 어기면 사이트의 푸시 권한을 취소합니다([Apple 공식 문서](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)). Chrome은 창이 focused일 때만 예외를 두지만 서비스워커에서 iOS를 가려낼 수 없어 분기하지 않습니다. 백엔드 명세의 "모르는 `type`은 무시"와 "앱 창이 보이면 목록만 다시 읽기"와 다른 점이라 백엔드에 알려야 합니다(전달 전). 알림은 가능한 한 일찍 띄우고(앱 창 조회를 기다리지 않음), 같은 `notificationIdx`는 `tag`로 한 개로 합칩니다. 열려 있는 앱 창에는 메시지로 알려 목록을 다시 읽게 합니다(Firebase SDK의 `onMessage`는 SDK가 만든 서비스워커 메시지만 받아서 이 구조에서는 쓰지 못합니다).
  - **만들 수 없는 푸시의 알림:** 모르는 `type`·읽지 못한 payload는 `notification`(콘솔 테스트 메시지 등)의 제목·본문을 쓰고, 그것도 없으면 제목만 "bigbird"인 일반 알림입니다. 새 `type`을 추가할 때는 이 서비스워커 문구와 앱 알림 목록(모르는 `type`은 목록에서 뺌)에 문구를 함께 추가해야 합니다.
  - **푸시 클릭:** 알림 목록 항목은 이동하지 않지만 푸시 알림은 눌렀을 때 등록 내역 `/campaign/{campaignIdx}`로 갑니다(사용자 확인 2026-11-19, 기획 최종 확인 중). `campaignIdx`가 숫자가 아니면 캠페인 현황 `/campaign`입니다.
  - **구조:** Firebase SDK는 `shared/api/firebase.ts`·`firebase-messaging.ts`에서만 import합니다(ESLint 허용 목록). 앱 생성은 `firebase.ts` 헬퍼 한 곳에서 이름별로 지연 생성하고(푸시는 `"push"` 앱), 권한이 허용되지 않은 사용자·미지원 브라우저·설정값이 없는 환경은 SDK를 불러오지 않습니다. Service Worker는 `public/firebase-messaging-sw.js`(Firebase SDK 없이 push 이벤트만 처리)입니다.
