# 마이페이지 API 검토

> V3 Swagger `V3-마이페이지` 그룹(Stage, 2026-10-23 재검토)에서 **Swagger만 봐서는 놓치기 쉬운 점, 아직 없는 API, 스펙과 다른 점, 백엔드 요청**만 적습니다. 엔드포인트·필드·응답 형태의 원본은 Swagger이고, Zod 스키마는 Swagger 필드를 기준으로 만듭니다.
> Swagger JSON은 `https://api.stage.client.bigbird.co.kr:38443/v3/api-docs/V3-마이페이지`에서 받습니다(UI는 `/swagger-ui/index.html?urls.primaryName=V3-마이페이지`).
> 화면 결정은 `specs/mypage/account.md`·`specs/mypage/subscribe.md`·`specs/mypage/money.md`에 있습니다.

## 1. 공개 범위

계정 설정의 Master 정보·정보 수정(휴대폰 인증 연결·이메일)·중복확인·비밀번호 변경·프로필 이미지·회원 탈퇴, 회사정보·서류 업로드·회사 분류, 계좌·은행 목록·통장사본, Sub ID 목록·검색·생성(프로필 이미지 포함)·삭제·권한 조회·수정(6개)·본인 정보 조회·수정(휴대폰·이메일·비밀번호)·본인 프로필 이미지, 캠페인 배정·해제·조회·캠페인별 배정 계정 조회, 알림 설정 조회·수정, 빅버드 머니 잔액·사용 내역·충전 내역·충전 요청 초기 데이터가 공개됐습니다(Sub ID 목록·본인 조회·권한·비즈머니 잔액·충전은 2026-10-23 추가). 대부분 v2 API를 그대로 재사용합니다.

## 2. 구현할 때 주의할 점

- **응답 형태가 두 가지입니다.** 비밀번호·프로필·Sub ID·Master 조회·알림 설정은 HTTP 상태 + `V3ErrorResponse {result:false, reason}`이고, 업로드·계좌는 **HTTP 200**에 `result`/`reason`으로만 성공·실패를 구분합니다. 업로드도 용량 한도(파일당 500MB) 초과만은 400 `{reason:"max upload size error"}`입니다. 두 형태를 모두 처리합니다.
- **중복확인(`POST /check/{type}`)은 `result: false`가 사용 가능, `true`가 이미 사용 중**입니다(2026-10-23 Swagger 명시). `result`가 없거나 null이면 사용 가능으로 읽지 않습니다. `type=pw`는 반대로 `true`가 현재 비밀번호 일치입니다.
- **`PUT /modify`는 이메일을 비워 보내면 기존 이메일이 지워집니다.** 휴대폰 인증만 바꿀 때도 현재 이메일을 함께 보냅니다. Sub ID는 이 API를 못 쓰고(403) `PUT /sub/{type}`을 씁니다.
- **회사정보 수정(PUT)은 전체 덮어쓰기**입니다. 보내지 않은 필드가 null이 되므로 항상 전체 필드를 보냅니다. 등록(POST)만 필수값(회사명·연락처·사업자 등록 번호·통신판매업 신고번호)을 검증합니다.
- **업로드는 회사정보가 먼저 등록돼 있어야** 됩니다(`extra information is not found`). 처음 등록할 때는 회사정보를 저장한 뒤 파일을 올립니다. 서버가 받는 형식은 pdf·tiff·png·jpeg·jpg·bmp·heic(불일치는 `fail image upload`)이고, 화면은 시안 안내대로 JPG·PNG·PDF 10MB로 더 좁게 먼저 막습니다.
- **계좌 등록의 정산 기간 거부가 `{result:true, reason:"denied"}`**로 옵니다. `result`만 보면 성공으로 착각하므로 `reason`도 확인합니다. 그 밖의 실패는 `{result:false}`만 오고 사유가 없습니다.
- **계좌 조회의 은행은 이름**으로 옵니다. 은행 목록에서 이름으로 `bankIdx`를 찾습니다. 통장 사본 파일명은 `bankBookFileName`으로 옵니다(이전 등록분처럼 없으면 "등록됨").
- Master 정보 조회는 **Sub ID면 403**입니다. 간편 로그인 연동 상태는 이 응답이 아니라 `GET /account/sns`(2026-11-02)로 읽고(카카오·네이버·구글·애플 4개 고정, 페이스북은 연동하지 않음), 담당자명은 `certification.name`, 가입일은 `user.created`입니다.
- 프로필 이미지는 Master가 `/profile`, **Sub ID 본인이 `/sub/profile`**입니다(서로 상대 경로는 403). 등록·수정·삭제가 각각 POST·PATCH·DELETE이고, 없는 상태에서 PATCH·DELETE는 404입니다.
- 회사 분류는 **최상위 목록 API만** 씁니다. 하위 분류 API는 쓰지 않습니다(시안의 Select 하나, 회원가입과 같음).
- 회원 탈퇴는 비밀번호 확인(`POST /check/pw`) 뒤 `PUT /exit`(응답 `{result, message}`)로 처리합니다. v2가 둘 사이에 부르던 `POST /transfer/false`(2020년 서비스 이관 거부 기록)는 v3에서 필요 없음으로 결정했습니다(2026-10-22). Stage 호출은 계정이 실제로 탈퇴되므로 확인 전입니다.
- **Sub ID 생성(`POST /sub`)은 multipart**입니다. 계정 정보는 JSON 파트 `request`, 프로필 이미지는 선택 파트 `profileImage`로 보냅니다. **이미지 저장만 실패해도 계정은 이미 만들어집니다**(400 `이미지 파일만 업로드할 수 있습니다.`·`파일 업로드 도중 예외가 발생하였습니다.`, 롤백 없음). 프론트는 이 둘을 생성 성공으로 처리합니다(다시 보내면 `existing id`). 용량 초과(`max upload size error`)는 계정이 만들어지지 않습니다.
- **알림 설정 수정(`PUT /agreement`)은 부분 수정**입니다. 바꾼 필드만 보내고 응답은 바뀐 뒤의 전체 4개 값입니다. 최초 조회면 서버가 4개 모두 `true`로 만들어 줍니다. 응답에 동의·철회 일자가 없어 토스트의 날짜는 v2처럼 바꾼 날(클라이언트 오늘)을 씁니다.
- **Sub ID 목록(`GET /sub`)은 `size` 기본값이 3**이라 페이지 크기(8)를 명시합니다. 검색은 `searchType` 없이 `keyword`만 보냅니다(2026-10-27 Swagger에서 `keyword` 통합 검색으로 확인). 응답 `sub[].userIdx`는 항상 null입니다.
- **Sub 본인 정보는 `GET /sub/self`**(SUB 전용, Master는 403)입니다. 아이디·담당자명(`name`)·이메일·휴대폰·프로필 이미지 주소(`profileImageUrl`)·생성일(`created`, 2026-11-03 Stage 추가)을 줍니다. **Sub 이미지는 여기서 읽고 `GET /profile`은 부르지 않습니다**(`/profile`은 세션의 회사(Master) 기준이라 Sub 토큰으로도 Master 이미지가 옴, 2026-11-03 백엔드 확인).
- **권한(`GET /authorization/{accountIdx}`·`PUT /authorization`)은 목록이 아니라 권한별 boolean 필드 6개**입니다(2026-10-27 배포: `isCampaignAccess`·`isInfluencerMatchingAccess`·`isInfluencerMarketAccess`·`isCommerceAccess`·`isBigbirdMoneyAccess`·`isPurchaserQuestionAccess`). `PUT`은 **바꾼 필드만 보내는 부분 수정**(하나도 안 보내면 400)이고 바뀐 뒤의 전체 값을 돌려줘 그대로 캐시로 씁니다. 권한 레코드(`access_menu`)가 없는 Sub ID는 조회·수정 모두 404 `access menu not found`입니다(§4-8).
- **빅버드 머니(`/bigbird-money`)** 4개 API(잔액 `GET`, 충전 내역 `POST /charge`, 사용 내역 `POST /usage`, 충전 요청용 `GET /init`)는 v2 `/biz/*`를 재사용합니다(2026-10-23 공개, 2026-10-29 Swagger 재확인). 화면에 필요한데 없는 API·필드·오류 형태는 [빅버드 머니 API 요구 명세](https://claude.ai/artifact/5qtCtjfY7hqEaigyv3xJk7)(Figma 3.0.9 기준, §4-16·§4-17)에 모았습니다.
  - **권한**: 빅버드 머니 권한이 없는 Sub ID는 충전 내역·사용 내역·`init`이 403(`V3ErrorResponse`)입니다. 잔액 `GET`은 헤더 표시용이라 막지 않습니다.
  - **잔액 `GET`(2026-10-30 오후 Stage 재배포)**: 응답은 `{bigbirdMoney, withdrawable, withdrawUnavailableReason}`입니다. 금액 필드 이름이 `bizMoney`에서 `bigbirdMoney`(원 단위 정수)로 바뀌었고, V2에 있던 `name`·`companyName`은 뺐습니다. `withdrawable`이 false면 "출금하기"를 비활성으로 두고, 이유 `withdrawUnavailableReason`은 `ZERO_BALANCE`(잔액 0원)·`PENDING_WITHDRAWAL`(처리 중인 출금 있음)이며 출금 요청 `POST /withdraw`의 409와 같은 기준입니다. 프론트는 `withdrawable`로 버튼만 막고 사유는 쓰지 않습니다.
  - **사용 내역(2026-10-30 14:52 재배포, 연결 완료)**: 사용·환급·충전·출금 건이 한 목록(완료된 충전, 운영자가 처리한 출금만)이고 항목 `id`(사용 내역 코드, 예 `BC-12345678901234`)는 충전·출금까지 고유해 그대로 키로 씁니다(명세 Q-7). `type`은 `USE`·`REFUND`·`CHARGE`·`WITHDRAWAL`(옛 "환불"은 `WITHDRAWAL`, Q-9), `campaignType`은 `recruit`·`pick`, `usageDetailCode`는 `INFLUENCER_CONTRACT_PICK`·`INFLUENCER_CONTRACT_RECRUIT`·`AI_MANUSCRIPT_CONFIRM`·`AI_POSTING_GUIDE` 4가지(옛 건이나 충전·출금은 `null`이고 `usageDetailName`이 서버 문구)입니다. 금액 `usageAmount`는 부호가 있고, 충전·출금은 캠페인 값이 모두 `null`입니다. `contractTarget`(`{name, influencerId}`)은 필드는 오지만 **연결 데이터가 없어 지금 항상 `null`**입니다(Q-10: 한 명, PICK형은 계약 대상마다 행이 따로). 상세 API는 만들지 않습니다.
  - **사용 내역 필터 선택지** `GET …/usage/filter-options`(`campaigns[{campaignIdx, campaignName}]`, `usageDetails[{code, name}]`)는 둘 다 읽습니다. 사용 내역 옵션의 값은 서버 `code`(요청 `usageDetailCode`에도 그대로), 라벨은 번역이 있는 코드면 번역·없으면 서버 `name`입니다.
  - **충전/출금 내역(`POST /charge`, 2026-10-30 Stage 재배포)**: 충전 건과 출금 건을 요청 일시 최신순 한 목록으로 줍니다. 요청은 `page`·`entrySize`(10·20·50, 기본 10)·`type`(`CHARGE`·`WITHDRAWAL`)·`startDate`·`endDate`(`yyyy-MM-dd`, 요청 일시 기준, 양 끝 포함)·`status`이고 조건은 함께 걸립니다(AND, 검색어 없음). 항목은 `id`(충전·출금 번호가 겹칠 수 있어 `{id, type}`이 키)·`type`·`status`(`PENDING`·`DEPOSIT_COMPLETED`·`DEPOSIT_EXPIRED`(입금 기한 날짜가 지난 미입금)·`WITHDRAWAL_COMPLETED`)·`requestDate`·`completedDate`·`expiredDate`·`amount`(부호 없는 양수)·`payMethod`(`VBANK`·`VCARD` 등, 출금은 null)·`bankName`·`accountNumber`·`holderName`(충전 입금자 명 / 출금 예금주 명)·`receiptUrl`(출금은 null)이고 값이 없으면 null입니다. 오류는 400 `reason` `INVALID_PAGE`·`INVALID_FILTER`·`INVALID_DATE_RANGE`, 403 권한 없는 Sub ID입니다. 승인 일자 필드(`approvedDate`)는 두지 않기로 했고(충전은 요청 일시와 같은 값, 출금은 승인 단계 없음, 2026-10-30), 상세 조회 API도 만들지 않습니다(목록 항목으로 상세를 그림). 응답 항목 스키마 이름 충돌(구독 결제 내역의 `Item`으로 잘못 나옴)은 2026-10-30 오후 재배포로 해결돼 Swagger가 `BigbirdMoneyHistoryItemV3`를 보여 줍니다. 미입금 취소(`DEPOSIT_EXPIRED`) 건의 `amount`도 요청 금액으로 옵니다(Swagger 명시, 시안 표는 "+0원"이라 기획 확인 필요). 영수증은 `receiptUrl`(이니시스 호스팅)을 새 탭으로 엽니다(화면은 입금 완료 건만).
  - **충전 요청은 V3가 프록시하지 않습니다.** `GET /init`의 `encryptUserIdx`로 결제 서버 `bigbird-pay-be`의 v3 전용 API `POST /v3/mypage/bigbird-money/pay`를 프론트가 직접 부릅니다(`isSSPayFlag`는 반드시 `false`, `paymentMethodType`은 `"BIZ"`, 응답은 가공 없이 INIStdPay에 넘김, §4-17). Swagger `init` 설명은 아직 옛 `POST /client/pay` 기준입니다. 결제 뒤 `redirectUri`로 돌아오면 잔액·충전 내역을 다시 부릅니다.
  - **출금 요청 `POST /withdraw`(2026-10-30 Stage 공개)**: 보유 잔액 **전액** 출금이고 **multipart**입니다. JSON 파트 `request`(`bankIdx`(`GET /account/bank/list`의 `idx`)·`accountNumber`(숫자만)·`accountHolder`·`amount`(화면에 보여 준 잔액))와 **필수 파일 파트 `bankBook`(통장 사본, pdf·png·jpg·jpeg·heic 등)**을 보냅니다. 응답은 `{id, requestDate, amount, status:"PENDING", balance}`이고 `requestDate`가 완료 알럿의 일시입니다. **잔액은 요청 때가 아니라 운영자가 처리(출금 완료)할 때 빠집니다**(응답 `balance`도 요청 전과 같음). 오류는 `reason`에 코드가 옵니다: 400 `INVALID_BANK`·`INVALID_ACCOUNT_NUMBER`·`INVALID_ACCOUNT_HOLDER`·`BANK_BOOK_REQUIRED`·`INVALID_BANK_BOOK_FILE`, 409 `ZERO_BALANCE`·`PENDING_WITHDRAWAL_EXISTS`(대기 중 출금이 있거나 연타)·`BALANCE_CHANGED`(`amount`가 서버 잔액과 다름), 403 권한 없는 Sub ID, 500(통장 사본 업로드 실패 포함). 예금주 일치 검증 코드는 없습니다. 출금 건은 충전/출금 내역 `POST /charge`에 `type: WITHDRAWAL`로 옵니다. 잔액 `GET`의 `withdrawable`로 출금 가능 여부를 알 수 있습니다(위 잔액 항목, §4-17 ⑦).
  - **사용 내역 목록 요청**: `page`·`entrySize`(10·20·50)·`type`·`startDate`·`endDate`·`campaignIdx`·`usageDetailCode`를 함께 걸 수 있습니다(AND). 검색어(`keyword`)는 2026-11-02 반영: 캠페인 명·캠페인 코드·사용 내역 문구를 부분 일치(대소문자 무시, OR)로 찾고 최대 100자(넘으면 `400 INVALID_FILTER`)입니다. `searchType`은 없어졌습니다.

## 3. 아직 없는 API

| 화면 | 필요한 것 | v2 참고 |
|---|---|---|
| 간편 로그인 | 연결 상태·연결·해제(카카오·네이버·구글·애플) | `GET /account/sns`, `POST·DELETE /account/sns/{platform}` (2026-11-02 공개) |
| 빅버드 머니 | Figma 3.0.9 기준: 사용 내역 고유 id·계약 대상 필드, 사용 내역 필터 선택지(캠페인 명·사용 내역). 상세 조회 API(충전/출금·사용)는 목록 항목으로 충분해 만들지 않음(2026-10-30). 요청 내용은 [API 요구 명세](https://claude.ai/artifact/5qtCtjfY7hqEaigyv3xJk7) A-1·A-4·A-6 | `/biz/init` + PG. v2에 출금 없음 |
| 구독 | 전부 | 없음(v2에 구독 개념 없음) |

캠페인 배정(`POST·DELETE /assign`)과 캠페인 조회(`GET /campaign`)는 공개됐고, 2026-10-23에 유형·상태 값이 보강됐습니다: 상품 유형은 `serviceIdx`(PICK형 = 10·14, 나머지는 모두 모집형), 세부 상품은 `mainServiceIdx`·`mainServiceName`(1 브랜드형, 2·6 공구형 등), 상태는 번역용 문자 코드 `matchStatusCode`(WAITING·IN_PROGRESS·COMPLETED·FAILED)·`postingStatusCode`(NONE·WAITING·IN_PROGRESS·COMPLETED)·`shopStatusCode`(WAITING·IN_PROGRESS·COMPLETED)가 있습니다. ## 4. 백엔드 요청 (스펙과 다른 점)
