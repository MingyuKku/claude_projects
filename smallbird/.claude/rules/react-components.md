# React 컴포넌트 설계

## Props

모든 컴포넌트는 이름 있는 `Props` 인터페이스를 선언합니다. 스타일을 받는 컴포넌트는 `className`을 열고 `cn`으로 병합합니다.

## 로직과 렌더링의 분리

- UI가 아닌 상태·로직(데이터 연동, 브라우저 API, 스토어 조합, 비동기 처리)은 커스텀 훅으로 뺍니다. 컴포넌트 본문은 "무엇을 그리는가"가 읽히게 두고, "어떻게"는 훅 안에 둡니다. 이 목적으로 래퍼 컴포넌트(컨테이너/프레젠테이션)를 만들지 않습니다.
- 훅 이름은 구현이 아니라 의도를 드러냅니다(`useLogoutAction`, `useOnlineStatus`).
- 페이지·위젯이 조립을 맡는다고 로직을 모두 품지는 않습니다. 위젯도 "책임과 크기" 기준을 적용합니다.
- 하위 표시 컴포넌트는 props만으로 렌더링하게 둡니다.
- 한 번만 쓰이는 몇 줄짜리 로직을 빼서 간접 층만 늘어난다면 빼지 않습니다. 함께 바뀌는 코드는 함께, 따로 바뀌는 코드는 따로 둡니다.

## 순수성

컴포넌트와 훅은 렌더 중에 순수해야 합니다(렌더 중 외부 값 변경, `ref.current` 읽기·쓰기, setState 금지). `eslint-plugin-react-hooks`의 `purity`, `refs`, `set-state-in-render`, `set-state-in-effect` 규칙이 집행하며, 위반은 규칙을 끄지 말고 구조를 고칩니다.

## React 19

- 폼 제출과 변경 요청은 Actions와 `useActionState`를 우선 고려합니다. 이미 SWR 뮤테이션으로 캐시를 관리하는 흐름이면 그 패턴을 따릅니다.
- 비동기 값이나 Context 구독에는 `use()`로 충분한지 먼저 봅니다.
- `ref`는 일반 prop으로 받습니다. `forwardRef`는 쓰지 않습니다.

## 상태

- 렌더 중에 계산할 수 있는 값은 `useState`로 복제하지 않습니다. 복제본은 원본과 어긋납니다.
- 상태를 직접 변경(mutation)하지 않습니다.

## 책임과 크기

- 컴포넌트가 하는 일을 "~하고 ~한다"로 적었을 때 서로 무관한 일이 셋 이상이거나, 서로 다른 이유로 바뀌는 코드가 한 본문에 섞이면 나눕니다(예: 키보드 대응·로그아웃·메뉴 항목 계산이 한 위젯에 있음).
- 줄 수는 점검 신호일 뿐 목표가 아닙니다. 파일이 300줄(공백·주석 제외)을 넘으면 ESLint `max-lines`가 경고하며, 이때 위 기준으로 책임을 다시 봅니다.
- 기존 파일에 기능을 더한 뒤 위 기준을 넘으면 같은 변경에서 고치지 말고(리뷰가 어려워짐) 작업 보고에 "리팩터 필요"로 적어 별도 작업으로 넘깁니다. 최소 변경 원칙을 구조 악화를 묵인하는 근거로 쓰지 않습니다.
