# 테스트 (Vitest · Testing Library)

## 위치

테스트는 대상 파일 옆에 `<이름>.test.ts(x)`로 둡니다(`__tests__/`나 최상위 `tests/` 폴더를 만들지 않습니다). 슬라이스를 옮기거나 지울 때 테스트가 함께 따라가고, 슬라이스 내부를 상대 경로로 임포트할 수 있기 때문입니다.

## 우선순위

1. **높음**: 트랜스포머, 상태 로직이 있는 커스텀 훅, 비즈니스 규칙
2. **중간**: 폼 검증·제출 흐름, 인터랙티브 피처, 에러 상태 UI
3. **낮음**: 로직 없는 스타일 래퍼 (테스트하지 않아도 됩니다)

## 작성 원칙

- 문구는 테스트 환경의 `ko` 리소스 기준 한국어로 찾습니다. 번역 키 문자열로 단언하지 않습니다(`.claude/rules/i18n.md`).
- 사용자가 보고 하는 것을 검증합니다. `getByRole`/`getByText`로 찾고, 상호작용은 `userEvent`를 씁니다. 내부 state나 구현 세부는 단언하지 않습니다.
- 모킹은 네트워크 경계(`@/shared/api`의 HTTP 클라이언트, fetcher)에서만 합니다. 같은 슬라이스의 내부 모듈은 모킹하지 않습니다.
- 슬라이스 내부 파일은 상대 경로로, 다른 슬라이스는 Public API(`index.ts`)로 임포트합니다.
- `shared/`·`entities/` 변경 시 소비처의 테스트까지 통과해야 합니다.
- 버그를 고칠 때는 먼저 실패하는 테스트로 재현합니다.

## 라우터 통합 테스트 (`src/app/router/*.test.tsx`)

앱 전체 라우트를 jsdom에서 그리는 테스트는 느리고(화면 코드 지연 로딩, 세션 확인), CI 러너는 로컬보다 5~7배 느립니다. 여러 화면을 한 테스트에서 오가면 테스트 제한 시간을 넘겨 간헐 실패합니다.

- 한 테스트는 **이동 한 번**만 검증합니다. 출발 화면에서 바로 시작하고(`renderRoute(경로)`), 뒤로가기는 방문 기록을 쌓아 시작합니다(`renderRoute([앞 경로, 현재 경로])`).
- 로그인이 검증 대상이 아니면 로그인 폼을 입력하지 않고 세션 모킹(`resetSession`·`mockSession`)으로 로그인한 상태에서 시작합니다. 로그인 흐름은 전용 테스트 하나가 맡습니다.
- 모듈 전역 상태(세션 모듈의 직전 확인 결과 등)는 `resetSession`이 테스트마다 비웁니다. 새 전역 상태를 만들면 초기화 지점도 함께 둡니다.
- 여러 화면을 잇는 사용자 흐름 전체는 E2E(실제 브라우저) 대상이며 jsdom 테스트로 대신하지 않습니다.
