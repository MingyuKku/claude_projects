# 번역 문구 작성

번역 리소스(`locales/*.json`)를 쓸 때의 기준입니다. 키 구조·namespace·포맷 등 다국어 전반은 `i18n.md`를 따릅니다.

## 번역 작성 흐름 (스펙 단위)

1. Figma 텍스트와 스펙의 문구(에러·빈 상태 등 Figma에 없는 문구 포함)를 `ko.json`에 키로 옮깁니다. Figma에도 스펙에도 없는 문구는 만들지 않고 질문합니다.
2. 뜻이 하나로 정해지는 일반 문구(버튼, 안내, 에러, 날짜·수량 표현)는 에이전트가 `en`·`ja`·`zh-CN`으로 바로 번역합니다. 아래 **간결한 번역** 기준을 따릅니다.
3. 서비스 고유 용어(서비스·기능·지표 이름, 캠페인 유형처럼 이 서비스에서 고유명사로 쓰는 말)는 용어집 표기를 씁니다. 용어집에서 "미정"이거나 없는 용어는 `docs/glossary-questions.md`에 한국어 원문·사용 위치·확인 질문을 중복 없이 모읍니다. 사용자가 나중에 한 번에 답할 수 있도록 누적하며 작업을 멈추지 않습니다. 답변 전에는 모든 언어의 번역 리소스에서 해당 용어의 한국어 원문을 유지합니다. 일반 문구는 계속 번역합니다. 답을 받으면 같은 변경에서 `docs/prd.md` 용어집과 번역 리소스를 갱신하고 질문 문서에 반영 결과를 기록합니다.

## 간결한 번역

Figma는 한국어 기준으로 그려져 버튼·탭 등의 폭이 한국어 문구 길이에 맞춰져 있습니다. 번역은 직역보다 **한국어와 비슷한 길이**를 우선합니다.

- 공간이 좁은 요소(버튼, 탭, 칩·배지, 메뉴 항목, 테이블 헤더, 폼 라벨, 토글, `placeholder`)는 같은 뜻을 전하는 가장 짧은 표현을 씁니다. 한국어 원문이 짧으면 번역도 짧게 맞춥니다.
- `en`: 동사 하나나 명사구로 씁니다(`저장하기` → `Save`, 저장 대상이 화면에서 분명하면 `변경사항 저장`도 `Save`). 관사·`please`·`Click to`·`your` 같은 군더더기를 뺍니다. `Information` → `Info`, `Application` → `App`처럼 널리 쓰이는 축약만 씁니다.
- `ja`: 체언으로 끝냅니다(`保存する` → `保存`, `削除します` → `削除`). 라벨에 `〜してください` 같은 정중 어미를 붙이지 않습니다.
- `zh-CN`: 2~4자의 관용 UI 용어를 씁니다(`保存`, `删除`, `返回首页`). `请`·`您的`처럼 없어도 뜻이 통하는 말은 뺍니다.
- 안내·에러처럼 여러 단어로 된 문장은 자연스러움을 지키되 같은 뜻의 짧은 문장을 고릅니다. 주어·정중 표현 반복을 줄입니다.
- 짧게 만들려고 뜻을 바꾸거나 빼지 않습니다. 임의로 만든 축약어(`Mgmt`, `Cnt` 등)도 쓰지 않습니다. 뜻을 지키면서 한국어 길이에 맞출 수 없는 문구는 임의로 줄이지 말고, 문구·언어별 표현을 확인 리스트로 정리해 사용자에게 보고합니다.
- 서비스 고유 용어는 길이와 관계없이 용어집 표기를 따릅니다. 너무 길면 용어집 표기를 바꿀지 사용자에게 질문합니다.
